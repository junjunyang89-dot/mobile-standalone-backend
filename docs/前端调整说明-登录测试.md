# 前端调整说明（登录自动化测试）

后端已支持：**执行时由前端传入手机号、验证码**，任务详情返回**执行结果（含截图路径）**。前端按下面几点调整即可。

---

## 一、执行登录测试时传入「手机号、验证码」

**接口：** `POST {baseUrl}/functional-test/execute`  
**请求体除必填项外，增加 `config`（推荐必传）：**

```json
{
  "scenarioId": "login_android",
  "deviceId": "当前选择的设备ID",
  "applicationId": "当前选择的应用ID",
  "config": "{\"phoneNumber\":\"12312340002\",\"verificationCode\":\"521758\"}"
}
```

- **config** 为 **字符串**，内容是 JSON：`phoneNumber`、`verificationCode`。
- 多部手机/多账号时：每次执行前由用户选择或输入手机号、验证码，前端拼成 config 传即可，无需改后端。
- 不传 config 时后端会用默认手机号、默认验证码。

**前端拼 config 示例（JavaScript）：**

```js
const config = JSON.stringify({
  phoneNumber: form.phoneNumber || '12312340002',  // 表单或默认
  verificationCode: form.verificationCode || '521758'
});
await fetch(`${baseUrl}/functional-test/execute`, {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    scenarioId: 'login_android',
    deviceId: selectedDeviceId,
    applicationId: selectedApplicationId,
    config
  })
});
```

**建议：** 在执行登录测试的页面增加「手机号」「验证码」输入框（可带默认值），提交时把这两个值放进 config 传给后端。

## 二、轮询任务详情并展示「执行结果」

**接口：** `GET {baseUrl}/functional-test/tasks/{taskId}`  

**响应在原有任务字段基础上，增加了「最近一次执行」的结果字段：**

| 字段 | 类型 | 说明 |
|------|------|------|
| **executionStatus** | string | 执行状态：COMPLETED / FAILED / RUNNING 等 |
| **reportPath** | string | 登录成功后的截图路径（如 `/tmp/screenshots/login_xxx.png`），可用来展示「执行结果」或下载截图 |
| **errorMessage** | string | 执行失败时的错误信息，可展示给用户 |
| **executionEndTime** | string | 执行结束时间 |

**前端建议：**

1. 执行后拿到 `taskId`，用定时轮询 `GET /api/functional-test/tasks/{taskId}`。
2. 当 `status === 'COMPLETED'` 且 `executionStatus === 'COMPLETED'`、`reportPath` 有值时：表示**登录成功并已截图**，可展示「登录成功」并可选展示/下载截图（若后端提供截图下载接口则用 reportPath 请求）。
3. 当 `status === 'FAILED'` 或 `executionStatus === 'FAILED'`：展示「执行失败」，并把 **errorMessage** 展示给用户。

**响应示例（任务已完成且登录成功）：**

```json
{
  "id": "任务UUID",
  "taskName": "登录测试(Android)",
  "status": "COMPLETED",
  "executionStatus": "COMPLETED",
  "reportPath": "/tmp/screenshots/login_xxx_1234567890.png",
  "errorMessage": null,
  "executionEndTime": "2026-02-03T17:30:00",
  "deviceId": "...",
  "applicationId": "...",
  "createdAt": "..."
}
```

## 三、停止当前测试（已有能力，确认调用即可）

**接口：** `POST {baseUrl}/tasks/{taskId}/stop`  
无请求体，用执行登录测试返回的 `taskId` 调用即可。  
前端若有「停止」按钮，请求该接口即可。

---

## 四、删除任务（先停止再删除）

**接口：** `DELETE {baseUrl}/tasks/{taskId}`  

- 后端会**先停止任务**（若正在运行），再删除任务及关联执行记录。
- 前端只需调用本接口一次，无需先调停止再调删除。
- **200**：删除成功；**404**：任务不存在。

**示例：**

```js
await fetch(`${baseUrl}/tasks/${taskId}`, { method: 'DELETE' });
```

---

## 五、测试任务列表（按截图方式：筛选 + 卡片展示）

**接口：** `GET {baseUrl}/functional-test/tasks?page=1&size=10`（支持分页，可选 `status`、`keyword`、`days`）

**可选查询参数（与截图中的筛选对应）：**

| 参数 | 类型 | 说明 |
|------|------|------|
| **days** | number | 时间范围：不传或 0=全部，3=近三天，7=近一周 |
| **keyword** | string | 任务名或备注关键词（模糊搜索） |
| **status** | string | 任务状态：COMPLETED（完成）、STOPPED（停止）、RUNNING（运行中）、PENDING、FAILED 等 |

**示例：**
- 全部：`GET /api/functional-test/tasks`
- 近三天：`GET /api/functional-test/tasks?days=3`
- 近一周：`GET /api/functional-test/tasks?days=7`
- 仅完成：`GET /api/functional-test/tasks?status=COMPLETED`
- 搜索：`GET /api/functional-test/tasks?keyword=登录`

**响应每条任务含：** id、taskName、remarks、platform、deviceId、applicationId、**deviceName**（设备名称，便于卡片展示）、status、createdAt、executionStatus、reportPath、errorMessage、executionEndTime。

前端可据此做卡片布局：任务 ID（id）、状态（status/executionStatus）、测试服务（taskName）、设备名称（deviceName）、创建时间（createdAt）、备注（remarks），并配合「删除报告」调用 `DELETE /api/tasks/{id}`。

## 六、小结与前端对接流程

| 操作 | 接口 | 说明 |
|------|------|------|
| **执行登录测试** | `POST {baseUrl}/functional-test/execute` | Body 含 scenarioId、deviceId、applicationId、**config**（手机号、验证码）。 |
| **轮询任务结果** | `GET {baseUrl}/functional-test/tasks/{taskId}` | 用 executionStatus、reportPath、errorMessage 展示结果。 |
| **停止测试** | `POST {baseUrl}/tasks/{taskId}/stop` | 无请求体。 |
| **删除任务** | `DELETE {baseUrl}/tasks/{taskId}` | 后端先停止再删除，前端只调一次。 |
| **任务列表（分页+筛选）** | `GET {baseUrl}/functional-test/tasks?page=1&size=10&days=3&status=COMPLETED&keyword=xx` | 分页：`content`、`totalElements`、`totalPages`、`page`、`size`；筛选：全部/近三天/近一周、状态、关键词；每项含 deviceName。 |

**删除任务对接流程：**

1. 用户点击「删除」某条任务（列表或详情页）。
2. 前端调用 **DELETE {baseUrl}/tasks/{taskId}**（无需先调停止）。
3. 若返回 200，从列表移除该任务或跳转列表；若 404，提示任务不存在。

更细的接口约定见：`docs/执行登录测试接口-给前端.md`。

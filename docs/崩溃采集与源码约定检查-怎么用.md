# 崩溃采集 & 源码约定检查：怎么用

两个功能都是**帮你发现“点击测试发现不了”的问题**。不用写新用例。

---

## 一、流程顺带抓崩溃（自动的，什么都不用点）

**它干什么：** 安卓流程用例跑的时候，顺便看 App 有没有崩溃、闪退、卡死。
以前流程“点得动”就算通过，中途 App 崩过一次也不知道。

**怎么用：** 照常跑流程用例就行。

**去哪看：** 「APP测试任务」→ 点那条任务的「查看详情」→ 执行日志**拉到最后**。

| 你看到 | 意思 | 该做什么 |
| --- | --- | --- |
| 绿色「崩溃采集：运行期间未发现崩溃 / ANR」 | 没崩 | 不用管 |
| 红色「应用崩溃」+ 下面一行「堆栈」 | App 崩了，任务会变成**失败** | 把这两行截图发给开发 |
| 红色「应用进程意外退出」 | App 自己没了（闪退），任务会变成**失败** | 同上 |
| 红色「ANR（应用无响应）」 | App 卡死过，任务**不会**因此失败 | 偶尔一次先观察，反复出现就提给开发 |
| 「本次未采集……（不代表没有崩溃）」 | iOS / 鸿蒙暂不支持，或没配包名 | 不是没崩，是没查 |

**第一次确认它在工作：** 跑一条安卓流程，看执行日志最后有没有「崩溃采集」这一行。有就是好的。

> 如果没有这一行：后端还没加载新代码，重启一下后端。

---

## 二、源码约定检查（手动点一下）

**它干什么：** 扫 Android 源码，数几样“不该变多”的东西。像体重秤：
今天记住 160，以后超过 160 就变红提醒。

| 检查项 | 为什么管 |
| --- | --- |
| X5 浏览器入口（现在 160 处） | X5 在部分手机上白屏，只许减不许增 |
| 空的 `onReceivedError`（现在 7 处） | 网页加载失败连日志都不留 |
| 两份 JSBridge 方法一致（各 23 个） | 改一份忘一份，某些页面功能就没了 |
| 服务端开关要登记（现在 5 个） | 每个开关的另一半分支没人测过 |

**入口：** 「APP测试任务」页 → 「任务类型」那一排最右边 → **「源码约定检查」**。

**第一次用（只做一次）：**
1. 点「源码约定检查」，等一两秒 → 顶部黄色「不完整」（还没定基准，正常）
2. 点「锁定基准」→「锁定」→ 顶部变绿色「干净」

**以后怎么用：** 发版前 / 每周点一次「重新扫描」。

| 顶部颜色 | 意思 |
| --- | --- |
| 绿色「干净」 | 没变差 |
| 红色「有风险」 | 有东西变多了，红色卡片里写着**哪个文件第几行**，发给开发问一句 |
| 黄色「不完整」 | 有规则没跑成或没锁基准，不能当通过 |

某一项**变少了**（显示「变好了」）→ 再点一次「锁定基准」，把新的低数字记下来。

> 注意：这里的结果是**风险**，不是 bug，不计入用例通过率。

---

## 遇到问题

- 找不到「源码约定检查」按钮 → 刷新页面（Cmd + R）
- 面板里报 404 / 执行日志没有「崩溃采集」→ 重启后端
- 其他 → 截图发给 AI 助手或开发

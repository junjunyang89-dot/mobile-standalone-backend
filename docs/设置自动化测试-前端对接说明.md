# 设置自动化测试 - 前端对接说明

**重要：** 「设置」自动化测试属于**功能基础质量测试**的一种场景，**不要做成独立模块**。  
前端**不应**在侧边栏增加「设置自动化测试」独立菜单，也**不应**做单独的「设置自动化测试」页面。  
正确做法：在**创建任务**时，任务类型为「功能基础质量」的前提下，在「测试场景」下拉中选择「设置测试(Android)」或「设置测试(iOS)」，选好设备与应用后创建任务，然后**运行该任务**，即表示在所选手机上执行设置自动化测试，结果在任务详情/执行日志中查看。

**baseUrl 示例：** `http://localhost:3000/api`

---

## 一、正确的前端形态（推荐）

「设置」只是**功能基础质量测试**下的一个**测试场景**选项，与「启动应用程序」「登录」「搜索」并列。

### 1.1 创建任务页（功能基础质量）

- 用户选择任务类型为「功能基础质量」后，有**测试场景**下拉框。
- 测试场景数据来源：`GET {baseUrl}/functional-test/scenarios/functional-quality`  
  返回中会包含（示例）：
  - `scenarioKey: "settings"`，`name: "设置测试(Android)"`，`platform: "ANDROID"`
  - `scenarioKey: "settings"`，`name: "设置测试(iOS)"`，`platform: "IOS"`
  - `scenarioKey: "settings_account"`，`name: "设置-我的账号(Android)"`，`platform: "ANDROID"`
  - `scenarioKey: "settings_account"`，`name: "设置-我的账号(iOS)"`，`platform: "IOS"`
- 用户选择**设备**、**应用**（需完美世界电竞）、以及**测试场景**后，提交创建任务。
- 创建任务请求：`POST {baseUrl}/functional-test/tasks`  
  请求体必须包含：`taskName`、`platform`、`deviceId`、`applicationId`、**`scenarioKey`**（选「设置测试」时传 `"settings"`，选「设置-我的账号」时传 `"settings_account"`，均小写）。

### 1.2 任务列表与运行

- 任务列表/详情中会返回 `scenarioKey`、`scenarioName`（如「设置测试(Android)”）。  
  前端可用 `scenarioName` 或标签「设置测试」展示，便于区分。
- 用户点击该任务的**运行**：调用 `POST {baseUrl}/tasks/{taskId}/run`。  
  后端会在**该任务所选的设备上执行设置自动化测试**（先登录再进入设置页并截图）。
- 无需单独「设置自动化测试」页面、无需单独「执行设置测试」按钮；**创建任务时选场景=设置 + 运行任务**即完成「在这部手机上执行设置自动化测试」。

### 1.3 查看结果

- 轮询任务状态/执行日志：`GET {baseUrl}/functional-test/tasks/{taskId}` 或 `GET {baseUrl}/functional-test/tasks/{taskId}/overview`。
- 用响应中的 **`executionLog`** 展示执行步骤。
- 最终截图地址：**`{baseUrl}/functional-test/tasks/{taskId}/screenshot`**（用作 `<img src="...">`，不要用 `reportPath` 当 URL）。

## 二、前端调整清单（设置作为场景，不做独立模块）

| 序号 | 前端要做的事 |
|------|----------------|
| 1 | **不要**在侧边栏增加「设置自动化测试」独立菜单，**不要**做单独的「设置自动化测试」页面。 |
| 2 | 在「创建任务」流程中（任务类型=功能基础质量），「测试场景」下拉增加选项：**设置测试(Android/iOS)**、**设置-我的账号(Android/iOS)** 等。数据来源：`GET {baseUrl}/functional-test/scenarios/functional-quality`，按 `platform` 与当前所选平台过滤。 |
| 3 | 选「设置测试」时传 **`scenarioKey: "settings"`**；选「设置-我的账号」时传 **`scenarioKey: "settings_account"`**（均小写）。未传或传错则执行时可能只跑「登录」不跑后续步骤。 |
| 4 | 任务列表/详情展示 `scenarioName` 或「设置测试」标签，与「启动应用程序」「登录」等场景并列。 |
| 5 | 运行、查看执行日志与截图：与现有功能基础质量任务完全一致（运行 → 轮询任务详情/overview → 展示 executionLog + 截图 URL）。 |

## 三、前置条件

- 应用：仅支持**完美世界电竞**（包名含 `steam.esports`），在「选择应用」中选该应用。
- 后端：`appium.enabled=true`，Appium Server 已启动，设备已连接。

---

## 四、直调接口（仅作备用，非主流程）

后端保留与旧项目一致的直调接口，仅用于**调试或兼容**，前端主流程**不要**依赖：

- `POST {baseUrl}/android-settings-test/execute`
- `POST {baseUrl}/ios-settings-test/execute`

请求体：`deviceId`（必填）+ `applicationId` 或 `packageName`/`bundleId`。  
响应：`{ code, message, data: { taskId, testSteps, reportPath } }`。

**再次说明：** 产品上应通过「创建任务时选场景=设置 → 运行任务」在所选手机上执行设置测试，不通过独立「设置自动化测试」模块或单独调用上述直调接口。

---

## 五、若只执行了登录、没有执行设置页步骤

- **原因**：执行时任务没有带 `scenarioKey=settings`，后端会走默认「仅登录」分支。
- **排查**：看任务详情或数据库里该任务的 `scenario_key` 是否为 `settings`；创建任务时请求体是否包含 `"scenarioKey": "settings"`。
- **解决**：创建「设置」任务时，接口 `POST /functional-test/tasks` 的 body 里必须包含 `"scenarioKey": "settings"`（小写）。后端会按小写匹配，存库建议也存小写。

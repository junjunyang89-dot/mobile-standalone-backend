# 跨平台与部署:问题与修复

> 两个约束是分开的:**客户端要跨 Windows/Mac**、**后端部署在 Mac Studio**。
> 后者意味着 macOS 专属的后端代码是可以接受的;前者不行。

---

## 〇、头号发现:现在打出来的 Windows 包,装上直接连不上

这条优先级高于我原计划的 E/G,因为它是**上线的硬阻塞**——一半人用不了。

```
scripts/build-installer.mjs 写的是   :3000
后端 application.yml 实际是          :3080
已打好的 Windows 产物里烧的是        http://192.168.3.107:3000/api
```

后端端口在 **2026-08-30** 从 3000 迁到 3080,前端代码全改了
(`workerSidecar.ts`、`api/index.ts`、`Settings.vue`、`Login.vue`),
**唯独漏了打包脚本**——那个文件最后一次改动是 8 月 16 日。

而且 `192.168.3.107` 是**打包那台 MacBook 的 DHCP 地址**:`detectLanIp()` 探测的是
打包机自己的 IP,不是 Mac Studio。

**Windows 用户的实际体验**:装好、打开、登录页左下角红点「连不上后端」。
Mac 用户一样坏,但 Mac 用户还有别的路,Windows 用户没有。

### 已修

端口改成 3080,并抽成常量 `CONTROL_PLANE_PORT` 注明"必须与后端 server.port 一致"——
下次迁移端口时这里不会再被漏掉。

**更重要的是把 `CONTROL_PLANE_URL` 改成必填,拿不到就终止打包。** 原先的 LAN IP 探测
比打包失败糟得多:

> 它会产出一个**看起来正常**的安装包,装到 50 台机器上全都指向打包那台 MacBook;
> 那台机器的 DHCP 一变,50 个客户端同时失效,而症状只是「连不上后端」,
> 没人会想到是打包时烧进去的地址。

少一个包比发出去 50 个错包好。另外加了两条不阻断的警告:
地址是 localhost/127.0.0.1 时提醒"这在别人机器上指向他自己";端口和后端不一致时提醒一句。

六种输入都验过:空 → 终止;`mac-studio.local` → 补成 `:3080/api`;
`192.168.10.5:9999` → 尊重你写的端口;完整 URL → 原样(缺 `/api` 会补)。

⚠️ **给 Mac Studio 配固定 IP 或内网域名**,别用 DHCP 地址打包。

## 一、设置页保存成功却说"保存失败"

这是上面那条的补救路径,而它本身在 Windows 上是坏的。

`Settings.vue` 原先 `await setControlPlane(...)`,worker 起不来就 `return`,
于是走不到最后那句 `ElMessage.success('已保存')`。而 `setControlPlane` 内部会
**死等本机 worker 健康检查 45 秒**。

Windows 用户(没装 JDK 17,worker 必然起不来)的体验:
填好地址点保存 → 转圈 45 秒 → 弹黄色「启动超时」→ **没有「已保存」**。
结论是"地址改不了",于是来找你——**而地址其实早就存好了**。

### 已修

两件事分开:地址先落地、先弹「控制面地址已保存」,worker 检查改成异步,结果回来再刷新状态。

而且 worker 起不来改成 `ElMessage.info` 而不是 `warning`——
**手机插在 Mac Studio 上时,本机 worker 不启动是正常状态**,报成警告会让人以为自己配错了。

## 二、让 Windows 用户零依赖

`App.vue` 原先无条件 `setWorkerBaseUrl(cfg.workerUrl)`,而 `workerUrl` 恒为
`http://127.0.0.1:3001/api`。而路由规则里 `/devices` 全部请求和「执行流程」都走 worker。

于是没有本机 worker 的机器上(Windows 没装 JDK 17 就是这种情况),
**设备管理页和执行流程直接是死的**——而手机本来就插在 Mac Studio 上,
压根不需要本机当执行节点。

更糟的是本机 worker 会**自己直连 Mac Studio 的 MySQL 3306**
(`workerSidecar.ts` 传 `DB_HOST`),也就是说走 worker 路线要让 50 台机器都能连生产库。

### 已修

改成**只有本机 worker 探活通过才指向它**,否则退回控制面——设备和执行都由 Mac Studio 负责,
这也是设备池的实际形态。

探活用 1.5 秒超时的直连 `fetch`,**不走 `node:worker-status`**:
后者内部会"顺便把 worker 拉起来"并死等 45 秒,放在启动路径上会让人以为应用卡死。

**这一改之后 Windows 用户零依赖**:不用装 Java,不用开放 MySQL。

## 三、Windows 上的双标题栏

`electron/main/index.ts` 只给 macOS 设了 `titleBarStyle: 'hiddenInset'`,
但 `MainLayout.vue` 的自绘标题栏是**无条件渲染**的。Windows 上 = 系统标题栏 + 38px 假标题栏叠着。

第一眼就能看见,而"看着像没做完"会影响 50 个人对平台的第一印象。已加 `v-if="isMac"`。

## 四、后端:一行 bug,上传成功但安装找不到文件

```
ApplicationController:31        @Value("${app.upload-dir:uploads/applications}")          ← 相对
AppPackageInstallService:76     @Value("${app.upload-dir:${user.home}/.mobile-standalone/...}")  ← 绝对
PgyerAppService:56              同上,绝对
```

**写入侧用相对路径,读取侧用绝对路径。** `app.upload-dir` 没配时(比如新机器上照
`application.yml.example` 重建配置),上传写到「项目根/uploads/」、安装去「~/.mobile-standalone/」读
→ **上传返回 200 成功,安装时说找不到文件**,而且 `git clean` 或换目录部署之后传过的包全没了。

已把默认值改成和另外两处一致。

## 五、新增 `/diagnostics/tools` 自检接口

这条是针对"**每个问题都会变成找你**"。

代码里有 **100 处**直接 `new ProcessBuilder("adb", ...)`。后端进程的 PATH 里没有 adb 时,
这些地方全部失败,表现是:设备列表空着、抓包一条都没有、元素点选没反应、性能采集没数据、
流程执行失败——**六个看起来互不相关的故障,同一个根因,而且一条报错都没有**
(`DeviceManager` 扫描失败只 `log.error` 然后返回空 List,而日志级别是 DEBUG,那行看不见)。

换机器部署时这几乎必然发生一次:

> 从登录 shell 跑起来的后端能看到 adb,而 launchd 开机自启拉起来的后端
> PATH 只有 `/usr/bin:/bin:/usr/sbin:/sbin`。**同一台机器、同一份代码,启动方式不同,结果就不同。**

### 判定逻辑做成了纯函数

核心是分清三种状态,因为**排查方向完全不同**:

| 状态 | 含义 | 该做什么 |
| --- | --- | --- |
| `OK_ON_PATH` | PATH 里就有 | 无 |
| `OK_OFF_PATH` | **装了,但后端进程看不见** | 配 PATH,别去重装 |
| `MISSING` | 真没装 | 去装 |

中间那个是最容易被误判的:现在的表现和"没装"一模一样,于是人会拿着"去装一下"的建议
去装一个已经装好的东西,装完发现还是不行,才开始怀疑 PATH——而那已经耗掉半天。

汇总也刻意分档:**可选工具没装不算红灯**。把"没装 solox"和"没装 adb"混成同一个红灯,
人第二周就不看这个接口了。

接口还会返回**后端进程自己看到的 PATH**——人对着它和终端里 `echo $PATH` 一比,
就知道是不是启动方式的问题,这比任何文字说明都直接。

### 为什么放在 `/diagnostics` 而不是 `/health`

`/health` 是**免鉴权**前缀(为了分清"服务挂了"和"令牌过期")。
而这个接口返回完整 PATH、SDK 绝对路径这些环境细节,挂在免鉴权路径上
等于把部署机的目录结构和用户名对内网所有人敞开。

放在 `/diagnostics` 要登录才能看。而**首次部署"还没建账号"阶段 `AuthFilter` 本来就整体放行**,
所以刚装完机器时照样 curl 得到——恰好是需要它的时候能用,建完账号之后收紧。

## 七、搬到 Mac Studio 需要准备什么

基于读到的代码,不是泛泛而谈。

### A. 运行时

1. **JDK 17**(`pom.xml` 锁的是 17,不是 21)、Maven
2. **Android SDK platform-tools** —— 关键是**让后端进程本身看到 adb**,不是只让终端看到。
   `export ANDROID_HOME=~/Library/Android/sdk`,PATH 加 `$ANDROID_HOME/platform-tools`;
   用 launchd 就写进 plist 的 `EnvironmentVariables`
3. `brew install mitmproxy`(抓包)、`appium`(会自动拉起)、`libimobiledevice`(仅 iOS)
4. 可选:`python3` + solox/tidevice(性能旁路,不装会静默回退 ADB 采集)
5. `node` + 在 `scripts/h5-playwright` 里 `npm install && npx playwright install`
   (`node_modules` 被 gitignore,不做这步 Web 测试是启动成功后才发现不可用)

### B. 配置(最容易漏)

6. **从旧机器直接拷 `src/main/resources/application.yml`,不要照 `.example` 重建。**
   `.example` 只有 41 个键,实际 272 个——用它重建会**启动成功但一堆功能静默不可用**
   (库连到公网旧机器、抓包抓不到、失败归因整块消失、截图保留天数从 90 掉到 7)
7. 启动前 `export AUTH_MAIL_PASSWORD='...'`(这个刻意不写在文件里)。
   **漏了的后果是 50 人里第一个点"忘记密码"的人永远收不到验证码**——而这恰好是新人接入最先用到的功能
8. `.db-profile.properties` 也被 gitignore,确认它和你要连的库一致

### C. 数据

9. 库结构不用动(38 张表会自建、存量表自动补列)
10. **处理 `apps.install_path` 里的旧绝对路径**:库是共享的,里面存的是
    `/Users/yangjun/.mobile-standalone/...`。新机器用户名不同的话,
    **历史 APK 全部装不上,而新传的没问题**——现象是"刚传的能装、以前传的都不行"。
    三个选择:新机器用户名也叫 `yangjun` / 跑一次 `UPDATE apps SET install_path = REPLACE(...)` / 重传

### D. 启动与验证

11. **用 `scripts/run-backend.sh` 启动**,不要裸 `java -jar`——
    有一批脚本路径是相对 `user.dir` 的(solox/tidevice/鸿蒙 bridge/H5),
    工作目录不对会静默降级
12. 启动后第一件事:`curl localhost:3080/api/diagnostics/tools`。
    这就是这次加它的原因——**先看清工具状态,再看设备列表**
13. **6 台设备逐台重新授权 USB 调试**。adb 的授权指纹是按主机的 `~/.android/adbkey` 记的,
    换机器后每台手机都要重新弹框点"允许",**这一步必须有人在现场**
14. 打客户端包时 `CONTROL_PLANE_URL=http://<Mac Studio 固定地址>:3080/api npm run build:installer`

## 八、还没修的(跨平台相关)

| | 问题 | 影响 |
| --- | --- | --- |
| **a** | **没有 `.ico` 图标,包未签名** | 能装上,但图标是 Electron 原子 + SmartScreen 蓝屏警告。50 人里必然有人在这步问"这是病毒吗"。**加一张 `build/icon.ico` 就行** |
| **b** | `usb` 原生模块打的是 macOS 二进制 | Windows 上 DeviceManager 恒为 null,点"连接设备"**什么都不发生、一个提示也没有**。但这层本身价值有限(`isAndroidDevice` 直接 `return false`),**建议直接删掉这个依赖**,统一走后端 adb |
| **c** | `taskManager.ts` / `database.ts` 是死代码 | `electronAPI.task` 和 `.db` 前端零引用。删掉能顺带砍掉 `better-sqlite3` + `electron-rebuild` 整串原生模块负担 |
| **d** | `/tmp/screenshots/perf_*` 永不清理 | 硬编码在 8 个类里,清理服务只扫顶层文件不递归。**两个月后磁盘满**,而且 `/tmp` 重启就没,报告页变破图 |
| **e** | `adb` 100 处裸调用 | 我加了自检接口让它**可诊断**,但没改那 100 处。`SdkTools.adb()` 已经有正确实现,只是 package-private 且只被模拟器代码用 |
| **f** | Redis 死配置 | `application.yml` 配了 Redis,但 pom 里没有依赖、代码零引用。**没有功能影响**,但部署的人会去找一台不存在的服务 |
| **g** | iOS WDA 签名 team 写死 | 3 处默认值只改对了 1 处。仅影响 iOS |

**我建议 a 和 d 在上线前做掉**:a 是 5 分钟(放一张图标),d 是磁盘会满的定时炸弹(先加个 cron 兜底也行)。

b + c 是一起做的清理,能让 Windows 包小一截、少一串原生模块麻烦。

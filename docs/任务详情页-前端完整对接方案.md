# 任务详情页 - 前端完整对接方案

本文档给出**任务详情页**的接口使用、数据映射和展示规则，前端按此改造即可与后端对齐。

**约定：** `baseUrl` 需带 `/api`，例如 `http://localhost:3000/api`。任务 ID 来自路由参数 `id`。

---

## 一、页面结构（建议）

```
┌─────────────────────────────────────────────────────────────────┐
│ ← 返回  任务标题（如「登录测试(Android)」）                        │
├─────────────────────────────────────────────────────────────────┤
│ 【蓝色信息卡】                                                    │
│ 左：任务标题、描述、Task-xxx  中：测试类型、应用包名/版本、API版本  │
│ 右：开始时间、持续时间、执行人、[环境参数] [执行日志]               │
├─────────────────────────────────────────────────────────────────┤
│ Tab: 概览  |  检测规则                                            │
├─────────────────────────────────────────────────────────────────┤
│ 概览：达标率区块 + 测试结果分布图                                  │
│ 检测规则：表格（测试项分类、测试项名称、测试结果、详细日志）        │
└─────────────────────────────────────────────────────────────────┘

弹窗/抽屉：执行日志（时间 + Level + 消息列表）、测试报告（执行日志 + 截图）
```

---

## 二、接口调用策略（最少请求）

| 步骤 | 接口 | 用途 |
|------|------|------|
| 1 | `GET {baseUrl}/functional-test/tasks/{id}/overview` | **必调**。拿整页：头部信息卡、达标率标题、统计、检测规则表、执行变量。 |
| 2（按需） | `GET {baseUrl}/functional-test/tasks/{id}` | 需要执行变量等时再调；**overview 已含 executionLog**，一般无需为「执行日志」单独请求。 |
| 2 备选 | `GET {baseUrl}/functional-test/tasks/{id}/execution-log` | 仅要执行日志列表时用，与 overview / 任务详情的 `executionLog` 一致。 |
| 3（按需） | 截图不单独请求 | 用 URL 作为图片地址：`{baseUrl}/functional-test/tasks/{id}/screenshot`，`<img src="...">` 即可。 |

**推荐：**

- 进入页时：只调 **overview**，用其渲染头部、Tab「概览」、Tab「检测规则」。
- 点击「执行日志」时：直接用 **overview** 返回的 `executionLog` 渲染（overview 已包含）；若未在首屏请求 overview 可再调任务详情或 `execution-log`。
- 测试报告/截图区块：直接用 `img.src = baseUrl + '/functional-test/tasks/' + id + '/screenshot'`，无截图时图片 404 显示占位即可。

## 三、overview 响应 → 页面映射

**请求：** `GET {baseUrl}/functional-test/tasks/{id}/overview`  
**404：** 任务不存在或任务类型不支持，前端展示「任务不存在」或返回列表。

### 3.1 蓝色信息卡

| 展示位置 | 接口字段 | 说明 |
|----------|----------|------|
| 左上 任务标题 | `title` | 如「登录测试(Android)」 |
| 左上 描述/备注 | `remarks` | 可为空 |
| 左上 任务 ID | `taskId` | 可格式化为 `Task-{taskId}` 或直接展示 |
| **左上 测试场景** | **`scenarioName`** | 如「设置-我的账号(Android)」「登录测试(iOS)」；无则展示「-」。另有 `scenarioKey`（如 settings_account、login）可按需使用。 |
| 中间 测试类型 | `testType` | 如「应用」「功能体验基础质量测试」 |
| 中间 应用包名 | `appPackageName` | 如 `com.pwrd.steam.esports` |
| 中间 应用版本 | `appVersion` | 如 `3.7.9.202` |
| 中间 API 版本 | `apiVersion` | 无则为 `null`，可展示为「-」 |
| 右侧 开始时间 | `startTime` | ISO 格式，可格式化为 `yyyy-MM-dd HH:mm:ss` |
| 右侧 持续时间 | `duration` | 如「1分4秒」 |
| 右侧 执行人 | `executor` | 固定「杨俊俊」 |
| 右侧 环境参数 | - | 暂无接口，可先占位或隐藏 |
| 右侧 执行日志 | - | 点击后请求任务详情或 execution-log，展示 executionLog |
| 右侧 **查看报告** | - | **必须**使用下方「五、查看报告」的 URL，**不要**用 reportPath 或文件名做链接，否则会 404 |

### 3.2 概览 Tab

| 展示内容 | 接口字段 | 说明 |
|----------|----------|------|
| 统计区块标题（红圈处） | `summarySectionTitle` | 如「功能质量达标率」「兼容性满足度」 |
| 实际测试项 / 通过 / 不通过 / 告警 | `compatibilitySummary` | `actualTestItemCount`, `passedCount`, `failedCount`, `warningCount` |
| 环形图 / 达标率 | 用 `compatibilitySummary` 计算 | 达标率 = passedCount / actualTestItemCount（注意除 0） |
| 测试结果分布柱状图 | `resultDistribution` | 每项：`categoryName`, `passed`, `warning`, `failed`, `deviceDependent`，按分类画柱状图，图例：通过(绿)、告警(橙)、不通过(红)、设备依赖(灰) |

### 3.3 检测规则 Tab（表格）

数据源：**testResultItems**（数组）。

| 表格列 | 接口字段 | 说明 |
|--------|----------|------|
| 测试项分类 | `testItemCategory` | 如「登录」「OS兼容」 |
| 测试项名称 | `testItemName` | 如「输入手机号」「输入验证码」 |
| 测试结果 | `testResult` | 通过 / 不通过 / 告警 / 设备依赖 / 未执行，可用不同标签色 |
| 详细日志 | **detailMessage** 优先，否则 detailLogLink | **有 detailMessage 时直接显示**（如 `138****8000`、`****(6位)`）；无则显示「-」或「查看」链接 |

**重要：** 手机号、验证码的脱敏值已放在对应行的 **detailMessage** 中，无需前端再拼。

## 四、执行日志（弹窗/抽屉）

**数据来源（二选一）：**

- `GET {baseUrl}/functional-test/tasks/{id}` → 取响应中的 **executionLog**
- 或 `GET {baseUrl}/functional-test/tasks/{id}/execution-log` → 响应体即为执行日志数组

**每条结构：**

| 字段 | 类型 | 说明 |
|------|------|------|
| step | string | 步骤名 |
| level | string | `Info` / `Error` |
| status | string | success / fail |
| message | string | 说明（含脱敏变量，如「已输入: 138****8000」） |
| selector | string \| null | 失败时未定位到的元素 |
| timestamp | string | ISO 时间 |
| screenshotUrl | string \| null | 该步骤截图地址（相对路径），有则用 `{baseUrl}/{screenshotUrl}` 作为 `<img src>` 展示该步截图 |

**展示建议：** 每行按参考样式展示为 **`yyyy-MM-dd HH:mm:ss` + 空格 + `level`（Info/Error）+ 空格 + 主文案**。主文案优先用 `message`（如「应用包名:com.xxx」「正在解析应用信息...」「报告已生成,任务完成」），`message` 为空时用 `step`。若存在 `screenshotUrl`，可在该步下展示小图（建议懒加载）；若 `selector` 有值，可换行或小字展示「未定位元素: selector」。可加 Level 筛选（如只显示 Info）。

**空态：** 接口保证 **executionLog 始终为数组**（无数据时为 `[]`），前端可直接用 `(data.executionLog || []).map(...)` 或判断 `data.executionLog.length === 0` 时提示「暂无执行日志」。

## 五、执行结果截图与「查看报告」

**图片/查看报告地址（必用此 URL，否则会 404）：**

```
{baseUrl}/functional-test/tasks/{id}/screenshot
```

示例：`http://localhost:3000/api/functional-test/tasks/xxx/screenshot`

**正确用法：**

- **查看报告**（点击「查看报告」）：链接地址或新窗口地址填 **`{baseUrl}/functional-test/tasks/{id}/screenshot`**（其中 `id` 为当前任务 ID）。若在新窗口打开，该 URL 会直接返回图片；若在页面内展示，用该 URL 作为 `<img src="...">`。
- **不要**使用接口返回的 `reportPath`（如 `/tmp/screenshots/login_xxx.png`）或仅用文件名（如 `login_xxx.png`）作为请求地址，后端不会根据纯文件名或 reportPath 路径解析静态资源，会导致 404。

**小结：** 前端只需用「任务 ID」拼出截图 URL：`baseUrl + '/functional-test/tasks/' + taskId + '/screenshot'`，无需使用 `reportPath` 字段。

---

## 六、测试报告区块（可选）

若单独做「测试报告」Tab 或区块，内容可由四部分组成：

1. **执行日志**：同上，用 executionLog 列表；每条若有 **screenshotUrl** 可展示该步截图（`<img src="{baseUrl}/{screenshotUrl}" />`，建议懒加载）。
2. **每步截图**：与执行日志一一对应，有 screenshotUrl 的步骤即可展示小图。
3. **执行结果截图（最终）**：同上，用 screenshot 的 URL。
4. **统计摘要**：与概览一致，用 overview 的 compatibilitySummary / resultDistribution。

数据均可从 overview + 任务详情（或 execution-log）拿到，无需额外接口。

## 七、前端改造清单（按顺序做）

| 序号 | 改动项 | 说明 |
|------|--------|------|
| 1 | 进入页只请求 overview | 用 `GET .../tasks/{id}/overview`，404 则提示并返回 |
| 2 | 蓝色信息卡 | 按 3.1 表用 overview 字段渲染 |
| 3 | 概览 Tab | 用 summarySectionTitle、compatibilitySummary、resultDistribution 渲染达标率与分布图 |
| 4 | 检测规则 Tab | 表格数据源 = testResultItems；「详细日志」列优先显示 detailMessage，无则「-」 |
| 5 | 执行日志入口 | 点击「执行日志」时请求任务详情或 execution-log，用 executionLog 渲染列表（时间 + level + message）；有 screenshotUrl 的步骤可展示该步截图（`{baseUrl}/{screenshotUrl}`，建议懒加载） |
| 6 | 截图与查看报告 | 最终截图与「查看报告」**统一使用** `{baseUrl}/functional-test/tasks/{id}/screenshot`（不要用 reportPath 或文件名），测试报告区用该 URL 作 img src，查看报告链接也用该 URL；每步截图用 executionLog[].screenshotUrl，404 做占位 |
| 7 | 环境参数 | 暂无接口，可占位或隐藏 |
| 8 | 空态 | executionLog 空、无截图、无 executionVariables 时做友好提示 |

## 八、接口与字段速查

| 接口 | 方法 | 说明 |
|------|------|------|
| 任务详情概览 | GET `/functional-test/tasks/{id}/overview` | 整页主数据，必用 |
| 任务详情 | GET `/functional-test/tasks/{id}` | 含 executionLog、executionVariables |
| 执行日志 | GET `/functional-test/tasks/{id}/execution-log` | 仅执行日志数组（含 screenshotUrl 时可为每步请求步骤截图） |
| 步骤截图 | GET `/functional-test/tasks/{id}/screenshots/{stepIndex}` | 某一步的截图，stepIndex 与 executionLog 下标一致 |
| 截图（最终） | GET `/functional-test/tasks/{id}/screenshot` | 最终结果截图 URL，直接给 img 用 |

**overview 重点字段：** taskId, title, remarks, testType, appPackageName, appVersion, apiVersion, startTime, duration, executor, summarySectionTitle, compatibilitySummary, resultDistribution, testResultItems（含 detailMessage）, executionVariables，**executionLog**（执行步骤日志，供「执行日志」弹窗展示；**始终为数组**，无数据时为 `[]`）。

按以上方案改造后，任务详情页即可与后端完整对接，并正确展示执行日志、手机号/验证码脱敏值和截图。

## 九、执行日志仍为空时排查

若前端「执行日志」仍显示为空，请按下面逐项确认：

1. **数据来源**：执行日志来自 **overview** 的 `executionLog`，或 **任务详情** `GET /functional-test/tasks/{id}`、**执行日志接口** `GET /functional-test/tasks/{id}/execution-log`。请确认前端取数用的是上述之一，且字段名为 **`executionLog`**（驼峰，数组类型）。
2. **任务已执行完成**：只有任务**执行完成**（成功或失败）后才会写入执行日志。若在任务「运行中」时打开详情，日志可能尚未写入，请等状态变为完成后再查看或刷新页面。
3. **任务类型**：当前仅**功能体验基础质量测试**会产出步骤日志；兼容性测试等类型不会写入 executionLog。请确认该任务为「功能体验基础质量测试」。
4. **历史任务**：本次改版**之前**已执行过的记录，数据库里可能没有 execution_log，接口会返回空数组 `[]`。请用**新执行一次**的任务验证。
5. **前端容错**：接口保证 `executionLog` 一定存在且为数组。建议前端使用 `const list = data.executionLog ?? []` 或 `(data.executionLog || [])`，再根据 `list.length` 判断是否展示「暂无执行日志」。
6. **后端日志**：部署后执行一次任务，若成功写入，后端会打日志：`任务执行成功，已写入执行日志: taskId=xxx, 条数=N`。若无该日志，说明未走写入分支（例如任务类型非功能体验测试）。

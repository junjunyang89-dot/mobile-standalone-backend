# 试跑跑完什么都看不见 —— 这是我上一轮改出来的

## 是我的问题

上一轮做「试跑不污染质量数据」时，我在 `TaskMapper.findLatestByFlowId` 上加了一句：

```xml
AND (run_track IS NULL OR run_track <> 'DEBUG')
```

意图没错：编辑器里调试挂几次，不该让通过率变难看、不该当成这条流程的「最近结果」、不该触发告警。

但这一条同时把试跑从**「我刚跑的那次呢」**里也摘掉了。而前端 `submitExecute` 拿到接口返回的 `taskId` 之后，只弹了一句「已开始执行」就把它扔了：

```ts
ElMessage.success(res.message || '已开始执行')
execVisible.value = false
```

于是：任务建了、也跑了、日志和截图都在库里 —— 界面上一点痕迹都没有。**「不算进质量数据」和「我看不见它」是两回事，我把第二件也顺手砍掉了。**

## 改了什么

### 1. 试跑完，结果就在原地弹出来

新组件 `FlowRunWatch.vue`。点完试跑，执行弹窗关掉，结果弹窗接上，每 2 秒自己刷新：

- **顶部一行结论**：通过 / 失败 / 执行中 / 本次不适用，加已用时长，右边一个「打开完整报告」
- **失败时直接摊开三样**：卡在第几步、哪一步、报什么错、当时的定位串，右边贴**那一步的截图**
- **步骤流水**：跑的时候是进度（第几步了），跑完是回放；可以「只看出问题的」；每步有截图的点开看大图

三样凑齐了才叫「知道问题在哪」。少一样，人就得再点几下去别处找 —— 而调试的时候人还在编辑器里，跳出去就是打断。

轮询用 `setTimeout` 链而不是 `setInterval`：后端慢的时候 interval 会把请求越堆越多。弹窗关掉、组件销毁、跑满 30 分钟，三种情况都会停。

正式执行也走这个弹窗（标题变成「执行结果」）—— 想立刻看到结果这件事，跟走哪条轨没关系。

### 2. 列表上也看得见试跑

后端 `last-runs` 现在返回两份：

| 字段 | 回答的问题 | 谁算数 |
| --- | --- | --- |
| `lastRunStatus` / `lastRunTaskId` | 这条流程的质量结论 | **排除**试跑 |
| `lastDebugStatus` / `lastDebugTaskId` | 我刚跑的那次怎么样了 | **只有**试跑 |

刻意做成两个查询。合成一个的话，两个问题必然有一个答错。

「最近结果」列：有正式结果就显示正式结果（实心标签，点进任务详情）；没有就退而显示 `试跑·失败` 这种描边标签，点开就是上面那个结果弹窗。试跑关掉弹窗时会自动补拉一次，免得列上还挂着旧的。

新增 `findLatestDebugByFlowId`，走已有的 `idx_flow_track(flow_id, run_track)` 索引。

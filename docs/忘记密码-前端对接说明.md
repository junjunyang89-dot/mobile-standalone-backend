# 忘记密码 / 绑定邮箱 — 前端对接说明

后端 P0 已完成。方案背景见 `忘记密码-设计方案.md`，这里只讲接口怎么调。

---

## 一、接口清单

| 方法 | 路径 | 是否要登录 | 用途 |
|------|------|-----------|------|
| POST | `/auth/forgot-password` | 否 | 申请重置验证码 |
| POST | `/auth/reset-password` | 否 | 用验证码改密码 |
| POST | `/auth/bind-email/code` | 是（任意角色） | 绑定邮箱第一步：发验证码 |
| POST | `/auth/bind-email/confirm` | 是（任意角色） | 绑定邮箱第二步：确认 |
| GET | `/auth/me` | 是 | 新增 3 个字段 |
| POST | `/platform-users/{id}/reset-password` | 管理员 | 行为有变化 |

## 二、忘记密码

### 2.1 申请验证码

```jsonc
POST /auth/forgot-password
{ "account": "yangjunjun" }        // 用户名或邮箱都收
```

**响应永远是这一个，不管账号存不存在：**

```jsonc
200 { "message": "若该账号存在且已绑定邮箱，验证码已发出，请查收（10 分钟内有效）" }
```

> ⚠️ **这句文案不要「优化」成「验证码已发送至 y***@pwrd.com」。**
> 那等于告诉任何人「这个账号存在、而且邮箱是这个」——这个接口不需要登录，
> 改完就是一个免费的账号枚举器。同理，前端也不要因为「没收到」就重试后给出不同提示。

发信是异步的，接口不等 SMTP，所以**响应很快返回不代表信已经到了**。

以下情况后端一律静默（响应完全相同，只在服务端日志留痕）：账号不存在、账号被停用、
账号没绑邮箱、60 秒内重复申请、该账号一小时内超过 3 次、该 IP 一小时内超过 10 次。

**前端要做的：** 点击后按钮进入 **60 秒倒计时**（和后端的重发间隔对齐），
并在页面上写清楚「没收到？检查垃圾箱，或联系管理员重置」。

### 2.2 用验证码改密码

```jsonc
POST /auth/reset-password
{ "account": "yangjunjun", "code": "482913", "newPassword": "xxxxxx" }
```

```jsonc
200 { "success": true, "message": "密码已重置，请用新密码登录" }
400 { "message": "验证码不对，还可以试 3 次" }
400 { "message": "验证码不对或已失效，请重新获取" }
400 { "message": "验证码错误次数过多，已失效，请重新获取" }
400 { "message": "密码至少 6 位" }
```

`message` 直接展示即可，剩余次数已经写在里面了。

**成功后跳登录页，不要自动登录。** 自动登录只省一步，却把「拿到那封邮件＝直接进系统」的窗口拉长。

⚠️ 一个反直觉但有意为之的点：**密码不合规时验证码也已经作废了**，用户要重新取一次。
顺序反过来（先校验密码格式）的话，就能拿一个已知不合规的密码去无限次试验证码。
前端应该在提交前先做一次本地格式校验，把这种情况挡掉。

## 三、绑定 / 更换邮箱

### 3.1 发验证码

```jsonc
POST /auth/bind-email/code
{ "email": "someone@pwrd.com", "password": "当前密码" }
```

```jsonc
200 { "success": true, "message": "验证码已发出，请查收" }
400 { "message": "当前密码不对" }
400 { "message": "这个邮箱已经绑在另一个账号上了" }
400 { "message": "邮箱格式不对" }
400 { "message": "发得太频繁了，请 60 秒后再试" }
```

**必须填当前密码**，这不是多余的一步：少了它，一个被借用的登录态就能把邮箱改成自己的，
再走忘记密码永久夺号——功能就从「找回密码」变成了「送出账号」。

### 3.2 确认

```jsonc
POST /auth/bind-email/confirm
{ "email": "someone@pwrd.com", "code": "123456" }
```

```jsonc
200 { "success": true, "message": "邮箱已绑定" }
400 { "message": "验证码与邮箱对不上，请重新获取" }
```

两步里的 `email` 必须一致——验证码是发到某个具体邮箱的，只能用来绑那个邮箱。

## 四、`/auth/me` 新增字段

```jsonc
{
  "email": "yangjunjun@pwrd.com",   // 可能为 null
  "emailBound": true,
  "mustChangePassword": false
}
```

- `emailBound === false`：**每次登录弹一次**「绑定邮箱，以便忘记密码时自助找回」，可跳过但不要不再提示。
  没绑邮箱的人忘了密码只能找管理员——这正是这次要减少的事。
- `mustChangePassword === true`：跳强制改密页，不可跳过（走已有的 `/auth/change-password`）。

> 注意：后端**目前还没有**在 `AuthFilter` 里拦截 `mustChangePassword` 的账号（属 P1）。
> 也就是说这一版只靠前端跳转，绕得过去。P1 补上之后，这类账号除
> `/auth/me`、`/auth/change-password`、`/auth/logout` 外一律 403。

## 五、管理员侧的变化

### 5.1 重置密码

```jsonc
POST /platform-users/{id}/reset-password
{ "password": "临时密码" }
→ 200 { "success": true, "message": "已重置，该账号下次登录会被要求先改密码" }
```

现在会自动置 `must_change_password = 1`。管理员设的密码管理员自己知道，
而且多半是通过 IM 口头告诉本人的——这是最常见的密码泄露路径，必须逼着改掉。
前端弹窗里把这句提示带上。

### 5.2 账号列表 / 新建 / 编辑加邮箱列

- `GET /platform-users` 返回的每条记录多了 `email`、`mustChangePassword`、`passwordChangedAt`
- `POST /platform-users` 新增可选字段 `email` —— **建议前端设为必填**，从源头堵住「没绑邮箱」
- `PUT /platform-users/{id}` 新增可选字段 `email`，传空串＝解绑

管理员填的邮箱视为可信，**不需要用户再确认**——账号本来就是管理员建的。

## 六、页面清单

| 页面 | 状态 | 说明 |
|------|------|------|
| 登录页 | **改** | 加「忘记密码？」入口。这是目前最大的可用性缺口——现在忘了密码的人在界面上找不到任何出路 |
| 忘记密码页 | **新增** | 三步同页：填账号 → 收验证码 → 填验证码 + 新密码；发码按钮 60 秒倒计时 |
| 强制改密页 | **新增** | `mustChangePassword` 时进入，不可跳过 |
| 我的账号 | **改** | 加邮箱绑定 / 更换（两步） |
| 账号管理 | **改** | 加邮箱列；新建/编辑表单加邮箱；重置密码弹窗带上「下次登录会要求改密」提示 |

## 七、部署前置

后端需要配置发信账号才会真发信（`application.yml` 的 `auth-mail` 段已经加好，密码走环境变量）：

```bash
export AUTH_MAIL_PASSWORD='...'
```

没配的话，`/auth/forgot-password` 仍然返回同样的文案（不能因为没配邮件就暴露账号是否存在），
但服务端日志会打 `[auth-mail] 未配置发信账号，验证码发不出去`。

**排查「用户说没收到」的顺序：**

1. 搜日志 `[auth-mail] 已发送` —— 没有就是压根没发（限流？没绑邮箱？账号不存在？往上翻 `[auth-reset]` 的日志）
2. 搜 `[auth-mail] 重试 N 次仍失败` —— 有就是通道问题
3. 两条都有「已发送」——那就是进垃圾箱了

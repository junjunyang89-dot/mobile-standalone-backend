# 「自动化用例」页下线 —— 改动说明

> 2026-09-05。起因：「流程编排是不是包含了自动化用例页面展示的数据」「流程编排里也可以执行，所以还是重复了」。
> 结论：**是重复的**。而且不止两个页面，是三个页面在做同一件事的三个残缺版本。

---

## 一、核实到的重复

| 页面 | 执行接口 | 能选包 | 执行参数 | 批量 | 看结果 |
|---|---|---|---|---|---|
| 流程编排 `UiFlows` | `/ui-flows/{id}/execute` | ✅ 蒲公英构建 | ✅ | ❌ | ❌ |
| **自动化用例** `AppAutomationCases` | 单条：同上<br>批量：`/online-regression/runs` | ❌ 两条都不能 | ❌ | ✅ | ✅ |
| APP回归 `AppOnlineRegression` | `/online-regression/runs` | ✅ 装包策略 | ❌ | ✅ | ✅ |

- 后端**只有一个**列流程的接口 `GET /ui-flows`，三个页面共用
- 「自动化用例」页 7 列里 5 列直接是 `ui_flows` 字段，「用途」就是 `catalog`
- 它的「编排」按钮跳 `/ui-flows?edit=<id>`，**编辑的就是同一行**
- 后端 `UiFlowController` 里那行注释写的是「**本页**单跑」——单数。这个接口设计时就假定只有一个页面调它

**「自动化用例」是三个里能力最弱的**：批量执行是回归页的子集（少了选包），单条执行是编排页的阉割版（少了选包和参数）。唯一独有的是「按环境·产品·平台筛选 + 最近结果列」，而**流程编排页本来就有全部筛选器**（还多了用途和名称）。

---

## 二、更深一层：执行没有分层

真正的问题不是页面多了一个，是**「执行」只有一种，而它应该有两种**：

- **试跑**：改完步骤跑一下看通不通。单条、手边设备、自己看一眼。
- **正式跑**：生产巡检 / 版本回归。一批、选环境包数据、要告警、进统计。

两种意图共用一个动作、一条轨，所以不管从哪个页面点做的都是同一件事——那页面当然重复。

**而且这在污染质量数据**：`findLatestByFlowId` 和工作台 7 天通过率都不过滤任何东西。你在编排页调试跑三次挂两次，那两次会被当成这条流程的「最近结果」，也会算进通过率。

## 三、后端改动

### 1. `RunTrack` 加 `DEBUG` 轨

刻意**不走** `normalize()`——那个方法是给批量执行定候选和排序的，把 DEBUG 塞进去会让每个调用点都要想一遍「试跑算哪条轨」，而答案是「都不算」。用独立的 `isDebug()`。

### 2. `/ui-flows/{id}/execute` 接受 `track`

```jsonc
{ "deviceId": "...", "track": "DEBUG" }   // 试跑
{ "deviceId": "..." }                      // 正式单跑，按自动化编排轨（存量行为不变）
```

### 3. 三处把试跑摘出去

| 位置 | 改动 |
|---|---|
| `TaskMapper.findLatestByFlowId` | `AND (run_track IS NULL OR run_track <> 'DEBUG')`，走已有的 `idx_flow_track` |
| `WorkbenchStatsService` 任务统计 + 最近失败 | 同上过滤 |
| `ExecutionAlertService` | 试跑失败不告警——你自己盯着屏幕在调，再推微信只会让人静音 |

> `AiTestCaseService.lastRunOf` 只认 `AUTOMATION` 轨，天然已排除，没动。

### 4. 批量执行支持执行参数

`StartRunRequest` 加 `params`，透传进这批里每条 task 的 config。

**顺序上批次参数垫底、账号参数覆盖**——账号是编排按设备分配的，让批次里手填的 `phone` 盖掉它，多台机会用同一个号互相踢下线，而现象是「登录成功后莫名其妙退出」，查起来完全想不到是这里。

## 四、前端改动

### 流程编排 `UiFlows.vue`

- **加「最近结果」列**，点击直接进任务详情（`TaskOverview`）。不 await，晚一点出来没关系但不能拖住整张表
- **「执行」按钮改名「试跑」**，弹窗里加「记入统计」开关，**默认关**
  - 关 = 试跑，传 `track: 'DEBUG'`
  - 开 = 正式单跑记录在案
  - 按钮文案跟着变：「开始试跑」/「开始执行」
- 筛选器不用加，本来就有

### APP回归 `AppOnlineRegression.vue`

加「执行参数」输入框（每行 `key=value`），补上它缺的那块能力。空行、`#` 注释、没有等号的行一律忽略——别让一个手滑的空格把整批跑挂。

### 下线 `AppAutomationCases`

- 菜单项移除
- **路由改成重定向到流程编排**，不是直接删。老书签和外部链接直接删会白屏，用的人只会来问你「页面怎么没了」
- `MainLayout` 里的 `isAppAutomationPage` 和 `.is-app-automation` 死 CSS 一并清掉
- **`AppAutomationCases.vue` 文件先留着**：路由摘掉后它已经不进构建产物了。跑一周确认合并后的页面没缺东西，再 `git rm`

## 五、验证情况

- **后端**：全量 411 个文件 javac，本次改动文件零个非依赖类错误（`OnlineRegressionOrchestrator` 那 3 条 `invalid method reference` 是改动前就有的 Lombok 产物，行号 256/275/946 一个没变）
- **前端**：`vite build` 在这边跑不了（macOS 装的 node_modules 缺 rollup 的 linux-arm64 原生包，npm 又被网络策略拦着装不上）。改用他 `node_modules` 里的 `@vue/compiler-sfc` **实际编译了三个改动的 SFC**（template + script setup 全过），`api/index.ts` 和 `router/index.ts` 用 TypeScript 的 parser 过了语法；并逐个核对了新增函数没有和原有的重名、`apiClient` 两处显式类型签名都补了新字段
- `vue-tsc` 跑不起来（`Search string not found` —— 它和装的 typescript 版本不兼容，**这是改动前就存在的问题**）

**请在本机跑一次 `npm run build` 和 `mvn compile` 做最终确认。**

## 六、你验证的时候

1. **试跑不进统计**：流程编排页点「试跑」（别勾"记入统计"），故意让它挂。看
   - 列表「最近结果」**不变**（还是上一次正式执行的结果）
   - 工作台 7 天通过率**不变**
   - 不收到告警
2. **正式单跑照常**：同一条流程，勾上「记入统计」再跑，这次「最近结果」应该更新
3. **最近结果可跳转**：点「失败」标签应该直接进任务详情
4. **老链接不 404**：浏览器直接访问 `/app-automation`，应该跳到流程编排
5. **批量执行传参**：APP回归页填一行 `phone=xxx`，跑一条用了 `${phone}` 的流程，看日志里是否用了这个值；再确认勾了账号池时**账号的号赢**

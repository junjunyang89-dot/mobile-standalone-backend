# 设备管理页 - 前端对接说明（直接按此接即可拿数据）

截图中的「设备管理」表格和「共 X 台设备」都来自下面两个接口。**baseUrl 必须带 `/api`**，例如：`http://localhost:3000/api`。

---

## 一、表格数据 + 「共 X 台设备」：用这一个接口即可

**接口（设备列表）：**

| 项目 | 值 |
|------|-----|
| **方法** | `GET` |
| **URL** | `{baseUrl}/devices` |
| **完整示例** | `http://localhost:3000/api/devices` |

**请求：** 无参数，无 body。

**响应：** `200`， body 为 **JSON 数组**，每项为一台设备。

**前端要做的事：**

1. **进入「设备管理」页时**（或该页挂载时）请求：`GET {baseUrl}/devices`。
2. **「共 X 台设备」**：用返回数组的 **length**，例如：`共${list.length}台设备`。
3. **表格数据源**：用该数组直接作为表格的 `data`，列与字段对应关系如下：

| 表格列名 | 接口返回字段 | 说明 |
|----------|--------------|------|
| 设备名称 | `item.name` | |
| 平台 | `item.platform` | 值：`ANDROID` / `IOS` / `HARMONYOS`，可转成中文展示 |
| 版本 | `item.version` | |
| 状态 | `item.status` | 值：`CONNECTED` / `DISCONNECTED`，可展示为「已连接」/「未连接」 |
| 最后可见时间 | `item.lastSeen` | ISO 时间字符串，可格式化后展示 |
| 操作 | - | 操作列用 `item.id` 做查看详情、连接/断开等 |

**响应示例（有数据时）：**

```json
[
  {
    "id": "6HJDU20409003857",
    "name": "SEA_AL10",
    "platform": "ANDROID",
    "version": "10",
    "status": "CONNECTED",
    "lastSeen": "2026-02-03T18:30:00",
    "config": null
  },
  {
    "id": "00008110-0006189002FB801E",
    "name": "iPhone8",
    "platform": "IOS",
    "version": "17.6.1",
    "status": "CONNECTED",
    "lastSeen": "2026-02-04T10:47:18",
    "config": null
  }
]
```

**无数据时：** 接口仍返回 `200`，body 为 `[]`，此时表格为空，显示「共0台设备」即可。

---

## 二、平台筛选（下拉选 Android / iOS 时）

若「平台」下拉选的是「Android」或「iOS」，可只请求该平台设备（可选）：

- **URL**：`GET {baseUrl}/devices/platform/ANDROID` 或 `GET {baseUrl}/devices/platform/IOS`
- **响应**：同上，仍是设备数组。表格和「共 X 台设备」仍用该数组的 length 和 list。

若不做筛选，只用一个接口 **`GET {baseUrl}/devices`** 即可，前端自己按 `platform` 过滤也行。

---

## 三、「刷新」按钮

点击「刷新」时：

1. 请求：`POST {baseUrl}/devices/scan`（无 body）。
2. 再请求一次：`GET {baseUrl}/devices`，用新返回的数组刷新表格和「共 X 台设备」。

---

## 四、自检清单（当前一条数据都没有时请逐项核对）

1. **请求是否发出**：在浏览器 Network（网络）里看是否有对 `.../api/devices` 的请求。若没有，说明前端没有在「设备管理」页调用该接口，需要在页面加载时调用 `GET {baseUrl}/devices`。
2. **URL 是否正确**：必须是 **`http://运行后端的地址:端口/api/devices`**，不能少 `/api`。例如本地后端：`http://localhost:3000/api/devices`。
3. **是否跨域**：若前端是单独起的（如 3001），后端在 3000，需后端配置 CORS 允许前端域名，否则浏览器会拦掉请求，Network 里可能看到请求失败或 CORS 报错。
4. **后端是否有设备**：用浏览器或 Postman 直接访问 `http://localhost:3000/api/devices`，若返回 `[]`，说明当前没有扫描到设备，需确认设备 USB 连接、Android 开启 USB 调试 / iOS 信任电脑，再点前端的「刷新」或等后端定时扫描。

---

## 五、总结：设备管理页用到的接口

| 用途 | 方法 | URL |
|------|------|-----|
| **表格 + 共 X 台设备** | GET | `{baseUrl}/devices` |
| 按平台筛选（可选） | GET | `{baseUrl}/devices/platform/ANDROID` 或 `IOS` 或 `HARMONYOS` |
| 刷新 | POST | `{baseUrl}/devices/scan`，然后再 GET `/devices` |

**直接给前端的接口就是：`GET {baseUrl}/devices`。** 用这个接口在「设备管理」页加载时请求一次，把返回的数组当作表格数据源，数组长度为「共 X 台设备」，按上表做列映射即可拿到并展示数据。

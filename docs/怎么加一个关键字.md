# 怎么加一个关键字

> 以这次新增的「区域内滑动」为例。**只需要写一个类，前端零改动。**

---

## 一、只有一个地方要动

```
src/main/java/com/mobile/standalone/service/keyword/handlers/XxxHandler.java
```

实现 `KeywordHandler` 接口 + 标 `@Component` 就完事了：

```java
@Component
public class SwipeInElementHandler implements KeywordHandler {
    public String code()  { return "SWIPE_IN_ELEMENT"; }   // 流程 steps 里引用的值
    public String nameZh(){ return "区域内滑动"; }
    public String category(){ return "ACTION"; }           // ACTION/WAIT/ASSERT/DEVICE/FLOW
    public String description(){ return "..."; }           // 面板上那句说明
    public int sortOrder(){ return 61; }                   // 面板排序，越小越靠前
    public boolean needsElement(){ return true; }          // 要不要绑元素
    public List<ParamDef> params(){ ... }                  // 参数契约
    public void execute(KeywordContext ctx){ ... }         // 干活
}
```

`KeywordRegistry` 的构造函数收的是 `List<KeywordHandler>`，Spring 会把所有 `@Component` 的实现自动注入进去——**没有任何名单要登记**。

以前这些东西散在四个地方（seed 字符串、执行器的 switch、三份平行的截图策略 switch），加一个关键字要改五处且互不校验。现在收成一个类了。

## 二、前端不用动

参数表单由 `KeywordParamFields.vue` 按后端下发的 `params()` 通用渲染，支持 `string / textarea / number / boolean / enum / element / steps` 七种类型，`withHelp(...)` 的文案会渲染成一个 hover 的问号气泡。

只有嵌套分支、多方式安装这类交互不是参数表能描述的，才需要 `customUi()` 返回 true 并在前端写专用编辑器。**普通关键字一律不需要。**

## 三、参数怎么写

```java
ParamDef.element("elementKey", "滑动区域元素")
        .withHelp("选金刚位那一条的容器，不是里面某个图标"),
ParamDef.enumOf("direction", "方向", List.of("left","right","up","down"), "left"),
ParamDef.number("durationMs", "单次滑动毫秒", 500)
        .withHelp("太快会被识别成快速甩动直接滑过头，太慢会被当成长按"),
ParamDef.bool("failOnMissing", "发现失效就让本步失败", false),
ParamDef.string("expected", "期望值"),
```

`withHelp` 别省。参数名对写的人是自明的，对三个月后第一次用它的人不是——**帮助文案是这个关键字唯一的说明书**。

## 四、执行体能拿到什么

```java
ctx.selector("步骤名")          // 元素的定位串（已含备选、变量已替换、随机下标已展开）
ctx.getDriver()                 // PlatformDriver，Android/iOS/鸿蒙差异已在驱动层消化
ctx.getDeviceId() / getPlatform() / getUiAppId()
ctx.str("x") / longParam("x", 默认) / boolParam("x", 默认)
ctx.substituted("x")            // 参数值里的 ${变量} 替换后
ctx.ok(标题, 详情)               // 记一条成功日志
ctx.warn(标题, 详情, 定位)        // 记一条告警，不中断
throw ctx.fail(标题, 详情, 定位, 错误摘要)   // 失败并中断
ctx.sleep(ms) / ctx.ensureNotCancelled()    // 等待要用它，能响应「停止」
```

**循环里一定要 `ensureNotCancelled()`**，否则点了停止还会继续跑完。

## 五、这次为什么要新加一个，而不是改 SWIPE

原来只有整屏滑动：

```java
// SwipeHandler → directionalSwipe(...)
case "left" -> { x1 = w * 0.82; x2 = w * 0.18; }   // 整个屏幕宽度
```

金刚位是首页上一条横向图标带，**整屏左右滑会被外层的 ViewPager 抢走**，结果是切到了下一个页签，而不是把这条带子往左推。想滑动某个区域，起点、终点和 Y 坐标必须<b>全部落在这个区域内</b>——这不是给 SWIPE 加个参数能表达清楚的事，两者的语义不一样。

顺带补了一个驱动层能力：`PlatformDriver.getElementBounds(deviceId, selector)` → `[left, top, right, bottom]`。
原来只有 `getElementCenter`，而**中心点只能告诉你从哪按下去，范围才能告诉你能在里面滑多远**。

## 六、写这类关键字时最容易漏的三件事

都是「不写也能跑，但会让人查半天」的：

1. **两端留白**。从区域最边上 1px 起手，很容易被系统边缘手势吃掉（Android 侧滑返回、iOS 边缘返回）。默认两端各留 10%。
2. **横滑锁 Y、纵滑锁 X**。偏一点就滑到隔壁控件上，而现象是「滑了但没反应」。
3. **区域太小要直接报错，不能假装成功**。滑一个 3px 的距离然后返回成功，是最难查的一类问题——你会先怀疑产品、再怀疑元素、再怀疑设备，最后才想到滑动距离根本不够。所以宽/高小于 60px 时直接失败，并且**把实际区域坐标打进错误信息**，让人一眼看出是选错了元素。

第 3 条的通用版本：**宁可报一个说得清的错，也不要返回一个说不清的成功。**

## 七、用法（金刚位左右滑）

1. 元素库里加一条元素，指向金刚位**整条容器**（不是里面某个图标）
2. 流程里加一步「区域内滑动」，绑这个元素，方向选 `left`
3. 想连滑几屏就把「次数」调大；滑不动时先看错误信息里的区域坐标对不对

方向语义和整屏「滑动」一致：`left` = 手指从右往左 = 内容往左走 = 看后面的。

### 滑动之后跳到别的页签了？——绑错层了

首页这类界面上常有**三层可横滑的东西套在一起**：

```
CS / DOTA2 / DEADLOCK 的页签 ViewPager     ← 绑到这层 = 整屏滑 = 切游戏页签
  └─ 金刚位那一条                            ← 要滑的是它
  └─ 资讯 / 动态 / 热评 / 视频 / 活动 的页签
```

绑错任何一层，表现都是「滑了，但滑的不是你想滑的东西」——**不会报错**，日志一片绿，
只有肉眼看截图才发现页面跳到别处去了。所以关键字加了一条保护：
**区域接近整屏时会打一条 warn**，告诉你多半绑到了外层容器。

找正确那一层，用：

```bash
python3 scripts/find_scroll_container.py \
    --base http://127.0.0.1:3000/api --device <deviceId> --token <token> \
    --text 完美开箱
```

它会从这段文案往上走祖先链，把每个 `scrollable=true` 的祖先按远近列出来，
**最近的那个标 ✅ 就是要绑的**，更外层的会标明「绑它就会滑错对象」。
典型输出：

```
✅ 绑这个 → 横滑条   1080×230 @(0,160)   id=entrance_list  class=RecyclerView
   （更外层）整屏/大块 1080×2190 @(0,150)  id=game_pager     class=ViewPager
```

一眼就能看出：`entrance_list` 高 230px（一行图标），`game_pager` 高 2190px（整屏）。

**如果祖先链上一个 scrollable 都没有**：说明这一条的可滑动性没体现在控件树上。
退而求其次绑那个「横滑条」形状的父容器，并把**两端留白调大到 25~30**——
滑动距离短了更像「条内滚动」，不容易被外层识别成翻页手势。

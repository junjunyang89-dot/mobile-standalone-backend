# 设置 / 设置-我的账号 / 设置-我的兴趣 / 设置-高校认证 - 前端改动说明

本文说明前端为支持「设置测试」「设置-我的账号」「设置-我的兴趣」「设置-高校认证」需要做的改动。**无需新增独立菜单或独立页面**，只需在现有「功能基础质量」创建任务流程中接入场景选项并正确传参。

**baseUrl 示例：** `http://localhost:3000/api`

---

## 一、前端需要做的改动（清单）

| 序号 | 改动项 | 说明 |
|------|--------|------|
| 1 | **测试场景下拉选项** | 在「创建任务」页（任务类型=功能基础质量），「测试场景」下拉中增加：**设置测试(Android/iOS)**、**设置-我的账号(Android/iOS)**、**设置-我的兴趣(Android/iOS)**、**设置-高校认证(Android/iOS)**。数据来自接口，见下文。 |
| 2 | **创建任务传参** | 选「设置测试」传 **`scenarioKey: "settings"`**；选「设置-我的账号」传 **`"settings_account"`**；选「设置-我的兴趣」传 **`"settings_interests"`**；选「设置-高校认证」传 **`"settings_school_cert"`**（均小写）。 |
| 3 | **任务列表/详情展示** | 任务响应中有 `scenarioKey`、`scenarioName`，用 `scenarioName` 展示（如「设置测试」「设置-我的账号」「设置-我的兴趣」「设置-高校认证」），与「启动应用程序」「登录」等并列。 |
| 4 | **运行与结果** | 运行、查看执行日志、截图方式与现有功能基础质量任务**完全一致**，无新接口。 |

**不需要做的：**

- 不要新增侧边栏「设置自动化测试」或「设置-我的账号」独立菜单。
- 不要做单独的「设置自动化测试」/「设置-我的账号」页面；都通过「创建任务时选场景 → 运行任务」完成。

### 2.1 测试场景列表（下拉数据来源）

**请求：** `GET {baseUrl}/functional-test/scenarios/functional-quality`

**响应示例（节选）：** 返回功能基础质量测试下的所有场景，其中与设置相关的包括：

- **前端用法**：用该接口作为「测试场景」下拉数据源；按当前表单所选**平台**过滤（只展示 `platform` 与所选平台一致的项）。
- **展示**：用 `name` 展示；提交创建任务时，将选中项的 **`scenarioKey`** 作为请求体的 `scenarioKey`。

### 2.2 创建任务

前端可能使用以下两种接口之一创建任务，**无论用哪个，都要在请求体中带 `scenarioKey`**，否则列表会显示「未选择场景」。

**方式一：** `POST {baseUrl}/functional-test/tasks`

| 字段 | 类型 | 说明 |
|------|------|------|
| taskName | string | 任务名称 |
| platform | string | ANDROID / IOS / HARMONYOS |
| deviceId | string | 设备 ID |
| applicationId | string | 应用 ID（须为完美世界电竞应用） |
| **scenarioKey** | string | 选「设置测试」传 **`"settings"`**，选「设置-我的账号」传 **`"settings_account"`**，选「设置-我的兴趣」传 **`"settings_interests"`**，选「设置-高校认证」传 **`"settings_school_cert"`**，均小写。未选场景可不传或传 null。 |

**方式二：** `POST {baseUrl}/tasks/test`（通用测试任务创建）

若创建任务走的是该接口，请求体同样需要带 **scenarioKey**，否则不会落库，列表会显示「未选择场景(ANDROID)」等。

| 字段 | 类型 | 说明 |
|------|------|------|
| taskName / remarks / taskType / platform / deviceId / appId / config | 同现有 | 按现有逻辑 |
| **scenarioKey** | string | 选「设置测试」传 **`"settings"`**，选「设置-我的账号」传 **`"settings_account"`**，选「设置-我的兴趣」传 **`"settings_interests"`**，选「设置-高校认证」传 **`"settings_school_cert"`**，均小写。 |

其他字段按现有逻辑即可。

### 2.3 任务列表 / 任务详情

任务相关接口（如 `GET {baseUrl}/functional-test/tasks`、`GET {baseUrl}/functional-test/tasks/{taskId}`）的响应中会包含：

| 字段 | 说明 |
|------|------|
| **scenarioKey** | 如 `"settings"`、`"settings_account"`、`"settings_interests"`、`"settings_school_cert"` |
| **scenarioName** | 如「设置测试(Android)」「设置-我的账号(iOS)」「设置-我的兴趣(Android)」「设置-高校认证(iOS)」 |

前端用 `scenarioName` 或自定义标签在列表/详情中展示即可。

### 2.4 运行任务与查看结果

- **运行：** `POST {baseUrl}/tasks/{taskId}/run`
- **轮询状态/日志：** `GET {baseUrl}/functional-test/tasks/{taskId}` 或 `GET {baseUrl}/functional-test/tasks/{taskId}/overview`
- **执行日志：** 使用响应中的 **`executionLog`** 展示步骤。
- **最终截图：** 图片地址为 **`{baseUrl}/functional-test/tasks/{taskId}/screenshot`**（用作 `<img src="...">`）。

与现有功能基础质量任务一致，无新增接口。

## 五、常见问题

**Q：选「设置」或「设置-我的账号」等后，列表里却显示「未选择场景」？**  
A：说明创建任务时 **scenarioKey 没有传到后端或没有落库**。若前端用的是 **POST /api/tasks/test**，请求体里必须带 **`scenarioKey: "settings"`**、**`"settings_account"`**、**`"settings_interests"`** 或 **`"settings_school_cert"`**（小写）；后端已支持该接口接收并保存 scenarioKey。若用的是 POST /api/functional-test/tasks，同样要带 scenarioKey。

**Q：选「设置」或「设置-我的账号」等后运行，只执行了登录、没有进设置？**  
A：多半是创建任务时未传或传错了 `scenarioKey`。请确认请求体里为 **`"scenarioKey": "settings"`**、**`"settings_account"`**、**`"settings_interests"`** 或 **`"settings_school_cert"`**（小写），且任务详情/列表中该任务的 `scenarioKey` 与预期一致。

**Q：是否需要为「设置」或「设置-我的账号」单独做页面？**  
A：不需要。在「创建任务」里选对应测试场景，然后像其他任务一样「运行」即可，结果在任务详情/执行日志中查看。

## 六、测试任务列表表格 - 增加「测试场景」列

在**测试任务**列表页的表格中，请增加一列 **「测试场景」**，便于区分同一任务类型下的不同场景（如设置测试、设置-我的账号、登录测试等）。

| 项目 | 说明 |
|------|------|
| **列名** | 测试场景 |
| **数据来源** | 任务列表接口 `GET {baseUrl}/functional-test/tasks` 返回的每条任务对象中的 **`scenarioName`** 字段。 |
| **展示建议** | 直接展示 `scenarioName` 的字符串；若 `scenarioName` 为空或 null，可展示「-」或留空。 |
| **示例** | 设置测试(Android)、设置-我的账号(iOS)、设置-我的兴趣(Android)、设置-高校认证(iOS)、登录测试(Android)、启动应用程序(Android) |

接口返回的任务对象中已包含 `scenarioKey`、`scenarioName`，无需额外请求。表格列顺序建议：任务名称、**测试场景**、任务类型、平台、状态、设备ID、应用ID、更新时间、操作。

**总结：** 前端只需（1）在功能基础质量创建任务页的「测试场景」下拉中展示并选择「设置测试」「设置-我的账号」「设置-我的兴趣」「设置-高校认证」等选项；（2）创建任务时把选中场景的 `scenarioKey`（`settings` / `settings_account` / `settings_interests` / `settings_school_cert`）传给后端；（3）在任务列表表格中增加「测试场景」列，绑定 `scenarioName`；（4）在任务详情用 `scenarioName` 展示。运行与结果查看方式不变。

## 七、后端确认：scenarioName 是否返回（排查「测试场景」列一直显示 -）

### 7.1 接口与字段

| 列表接口 | 说明 |
|----------|------|
| **GET {baseUrl}/tasks** | 通用任务列表（支持分页 `page`、`size` 及筛选）。返回每条任务的 `scenarioKey`、**scenarioName**。 |
| **GET {baseUrl}/functional-test/tasks** | 功能测试任务列表（分页、status/keyword/days 筛选）。返回的 `content[]` 中每条对象含 **scenarioKey**、**scenarioName**。 |

两个接口都会在每条任务对象里带上 **scenarioName**（展示名，如「设置测试(Android)」「设置-我的账号(iOS)」）。前端「测试场景」列绑定 `scenarioName` 即可；无则显示 `-`。

### 7.2 为什么一直显示「-」？

后端逻辑是：**仅当该任务在库里有 `scenario_key` 且 `platform` 时**，才根据场景键+平台解析出 `scenarioName` 并返回；否则 `scenarioName` 为 `null`，前端就会显示 `-`。

常见原因：

1. **库里这条任务是老数据**：在加「测试场景」之前创建的任务，当时没有保存 `scenario_key`，库里 `scenario_key` 为空，接口里 `scenarioName` 就是 `null`，前端只能显示 `-`。
2. **创建任务时没传 scenarioKey**：若创建走的是 `POST {baseUrl}/functional-test/tasks` 但请求体未带 `scenarioKey`，或带错字段名，则新任务也不会存场景，列表里同样为 `-`。

### 7.3 建议排查步骤

1. **确认接口是否带 scenarioName**  
   在浏览器开发者工具 → Network 中找到任务列表请求（`GET .../tasks` 或 `GET .../functional-test/tasks`），看响应里第一条任务对象是否包含 **scenarioName** 字段（值可为 `null` 或字符串）。
   - **没有该字段** → 需确认前端调的是上述两个接口之一，且后端版本已包含「列表/详情填充 scenarioName」的改动。
   - **有该字段但多为 null** → 多为老数据或创建时未传 `scenarioKey`，见下。

2. **用新任务验证**  
   新建一条任务：任务类型选「功能基础质量」，测试场景选「设置测试(Android)」「设置-我的账号(iOS)」「设置-我的兴趣(Android)」或「设置-高校认证(iOS)」等，再提交。  
   若创建接口会存 `scenario_key`（如 `settings` / `settings_account`），则该新任务在列表接口中的 **scenarioName** 应有值（如「设置测试(Android)」）；若新任务仍是 `null`，则需检查创建任务接口是否把 `scenarioKey` 写入库。

3. **老任务**  
   历史任务若库里没有 `scenario_key`，要么在后端做一次历史数据补偿（按业务规则补写 `scenario_key`），要么接受这些任务在「测试场景」列显示 `-`。

**后端已做：**  
- `GET /api/tasks`（含分页）：返回前对列表调用 `fillScenarioName(list)`，每条任务带 `scenarioName`。  
- `GET /api/tasks/{id}`：返回前对单条任务填充 `scenarioName`。  
- `GET /api/functional-test/tasks` 与 `GET /api/functional-test/tasks/{id}`：`TaskResponse` 中在 `toResponse(task)` 时根据 `task.scenarioKey` + `task.platform` 设置 **scenarioName**。  

因此，只要库里该任务有 **scenario_key** 和 **platform**，接口就一定会返回 **scenarioName**；没有则返回 `null`，前端显示 `-` 为预期行为。

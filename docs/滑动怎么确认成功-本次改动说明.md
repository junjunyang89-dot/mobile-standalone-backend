# 滑动怎么确认成功了 —— 本次改动说明

## 先把问题拆成两个

你问的「滑动过程中怎么确定我确实成功了」，里面其实是两个不同的问题，混在一起想会绕不出来：

| 问题 | 问的是 | 怎么答 |
| --- | --- | --- |
| ① 手势生效了吗 | 页面到底动没动 | 滑动前后对比这块区域的文案。**已有**，`verifyChanged`，默认开着 |
| ② 滑到目标了吗 | 想看的那个东西露出来了没有 | 需要一个**停止条件**，不是一个固定次数 |

①在上一轮已经做完了：滑完发现区域内容一个字没变，会告警并按概率列出三种成因。
②是这次加的。

## ②为什么不能用「滑 N 次 + 断言」

这个写法看着很自然，其实同时踩两个坑：

- **N 猜少了**：目标还没滑到，断言红了。但这不是缺陷，是次数填少了——你要去改用例，而不是提 bug。
- **N 猜多了**：滑过头，目标被推出屏幕，断言同样红。

而 N 本来就不该由人猜：这一条上有几个图标、这台手机屏幕多宽、上次跑完停在哪，写用例的时候都不知道。

所以正确的问法不是「滑几次」，是「**滑到它出现为止**」。这一步本身就是断言——出现了才算成功，不用再补一条。

## 改动一：区域内滑动加了「停止条件」

`SWIPE_IN_ELEMENT` 面板上多了一个 **停止条件**：

- **fixed（固定次数）** —— 就是原来的行为，存量流程一个字都不用改，默认走这条。
- **until（滑到它出现为止）** —— 选目标元素，滑到它露出屏幕就停。

选 until 之后多出三个参数：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 滑到它出现为止 | — | 目标元素 |
| 最多滑几次 | 10 | 兜底上限，正常滑到就停 |
| 没滑到是否失败 | 是 | 关掉就只告警不中断 |

两个细节值得说一下，因为它们决定了这东西准不准：

**「出现」只认屏幕内可见的。** 横滑条（HorizontalScrollView、没开回收的 RecyclerView）会把屏幕外的图标**原样留在控件树里**，坐标是负数或者大于屏宽。只问「存在吗」的话，一次都没滑就返回 true，然后报成功——用它验证滑动效果，结果是滑没滑都绿。所以判定用的是**元素中心点落不落在屏幕内**。

**滑到头会立刻停。** 到底之后再滑，区域内容不会再变。不停的话要白跑完 10 轮，最后只给一句「没找到」；而真正的原因——「已经到头了，后面没有这个东西」——反倒没人说出来。现在它会直接告诉你到第几次滑到头的。

## 改动二：新增「批量元素断言」关键字

`ASSERT_ELEMENTS_EXIST`，对应你说的「我会提供一批元素，如果这批元素出现了就表示成功」。

**为什么不是写 5 条「等待元素」**：一条条写，第 1 条不过就中断了，你只知道第 1 个没出现，剩下 4 个在不在没人告诉你。而排查时最想知道的恰恰是——**是全军覆没（页面根本没加载 / 滑错了地方），还是只少了一个（那一个的定位过期了）**。这两种情况的下一步动作完全不同。所以这个关键字把该看的都看完再报，失败文案里点名到具体是哪几个。

三种判定：

| 判定 | 用在哪 |
| --- | --- |
| **都要在（all）** | 进到某个页面后校验页面完整性 |
| **有一个就行（any）** | AB 实验、分版本文案、随机运营位；**横滑条也该用它** |
| **都不在（none）** | 校验东西确实消失了：退出登录后个人信息、删除后的列表项。这类断言漏写，是「删除功能坏了但用例全绿」的常见成因 |

参数里有个 **只认屏幕内可见的**，默认开着，原因同上——关掉它，人眼看不到的元素也算存在。

### 一个提醒：横滑条别用 all

你原话是「这批元素出现了就表示成功」。但横滑条上**同时可见的就那么几个**，滑到后面的时候前面的已经出屏了。整批要求 all，必然失败。横滑场景要么用 any（这一段里至少露出一个），要么每滑一段断言当前该露出的那一个——而后者其实就是「滑到它出现为止」，一步顶两步。

## 你的金刚位现在该怎么写

前提还是那句：**先确认绑对了元素**。上一轮加的 `requireScrollable` 会在 `scrollable=false` 时直接报错并告诉你实际坐标，配合 `scripts/find_scroll_container.py --text <这一条上的某个文字>` 能定位到真正可滑的那一层。

绑对之后，两种写法：

**这一条确实能滑** —— 用停止条件 until：

```
区域内滑动
  滑动区域元素 = 金刚位容器
  方向 = left
  停止条件 = until
  滑到它出现为止 = 金刚位最后一个图标
  最多滑几次 = 6
```
一步搞定，不用再补断言。滑到了就是成功，到头了没找到会明确告诉你「已经到头了」。

**这一条根本不滚动**（5 个图标正好铺满，这也是很可能的结果）—— 那就别滑了，直接断言它们都在：

```
批量元素断言
  要判定的元素 = 图标1、图标2、图标3、图标4、图标5
  判定方式 = all
  只认屏幕内可见的 = 开
```

第二种不丢人。金刚位不滚动的话，「能滑动」本来就不是这个页面的需求，硬写一条滑动用例只会长期偶现红。

## 顺带修的

- 次级元素下拉的提示语原来固定写着「留空则点自己」。那是「断言元素状态」那个关键字的语义，出现在「滑到它出现为止」旁边是错的——留空的含义各关键字不同，改成由各自的 help 去说。

# AI 编排：找到了真正的原因，不是提示词

> 结论先说：**「AI 编的流程根本跑不起来」是一个解析 bug，不是模型编错了。**
> 提示词那三轮，有一部分力气花在了错的地方。

---

## 一、真正的原因：子步骤在落库前就被丢掉了

`AiFlowComposer.parseSteps` 里原来是这么一行：

```java
params.put(f.getKey(), f.getValue().isNumber()
        ? f.getValue().numberValue()
        : f.getValue().asText());   // ← 这里
```

Jackson 对**数组和对象节点**的 `asText()` 返回的是**空字符串**。

也就是说：模型哪怕把 `thenSteps` 完完全全写对了，走到这一行也会被拍成 `""`。
落进库的流程里，判断分支是空的。

**这个 bug 特别隐蔽**，因为它看起来是对的：

- 外层大纲步数一步不少
- 关键字、元素全都合法
- 校验器也查不出来——它拿到的 `thenSteps` 已经是空的了，
  而空分支这条规则我上一轮才加，加之前连告警都没有

只有点进那一步，才会发现里面什么都没有。

**所以我上一轮说「根本原因是提示词没告诉模型 params 可以嵌套」——那句话是错的。**
提示词该补，但它不是这条流程跑不起来的原因。

已修：`toJava(JsonNode)` 递归还原，数组、对象、数字、布尔各归各位。

---

## 二、另外两处：校验器在给正确写法挑毛病

你截图里那条流程用的是「**一个元素 + 文案变量**」——
`mall_category_tab` 一个元素，靠 `${mall_category_tab}` 的值区分 CS商城 / 刀塔商城。

这是平台本来就支持的机制（`KeywordContext.locatorParams`：本步参数覆盖流程参数），
也是你们用得最多的写法。

但校验器会对这种步骤挑**两处毛病**：

| 它说 | 实际 |
| --- | --- |
| 「多了个用不上的参数 `mall_category_tab`，执行时会被忽略」 | 它正是用来填定位变量的 |
| 「这些变量没给值：`mall_category_tab`」 | 这一步已经给了 |

两条都是错的。后果不只是噪音——**AI 照着你的正确写法编出来的草稿，反而会被挑毛病**，
你看到提示只会以为是 AI 编错了，然后去改一个没问题的地方。

已修：定位里的 `${}` 变量认出来，本步 params 算「已提供」。
同时保住了反向：真没给值的变量照样提示，名字拼错的参数照样提示。

---

## 三、改成「抄你的流程」，不再堆规则

前三轮我都是在猜你们的惯例，然后写成提示词规则。这个循环不收敛——
猜一条补一条，你一跑就发现还差别的。因为惯例是隐性的，它只存在于**已经编好的流程里**。

现在改成：**生成时从库里挑 2~3 条同应用、已启用的人工流程，原样贴进提示词当范例。**

挑选规则：

- `enabled=true`（停用的多半是编废了或没调通，拿它当范例等于固化没验证过的写法）
- 非组件、3～30 步
- **排除 AI 自己生成的草稿**（按描述前缀识别）
- 排序**优先带嵌套分支的**——那正是模型最不会写、而你写得最多的结构

### 排除自己产物这条，是这里最要紧的一行

不排除的话会形成闭环：

```
模型编错 → 进库 → 下次当「人工范例」喂回去 → 错误被当成惯例学走 → 编得更错
```

**这种退化没有任何报错**，只会表现为「AI 越编越差」，查都没法查。

### 好处不只是准

范例**跟着你们的惯例自动更新**。以后你们改了写法，范例跟着变，不用再改这里一行代码——
而我手写的那些规则，每次都得我来改。

## 四、提示词补了三段（都是截图里有、我之前没写的）

**1. 同类控件用一个元素 + 文案变量**

并且「可用元素」清单现在会把定位里的 `${}` 变量**直接标出来**：

```
- mall_category_tab → 商城分类Tab · page_mall · 文案变量: mall_category_tab（用这个元素时要在本步 params 里给它赋值）
```

不标的话模型只有两条路：去找一个叫「刀塔商城」的元素（库里没有，打回重来），
或者自己猜变量名（拼错就是运行时报缺变量）。

**2. `SWIPE` 和 `SWIPE_IN_ELEMENT` 的区别**

横排 Tab 条、金刚位用区域内滑动。整屏滑会被外层容器抢走手势，结果是翻页。

**3. `IF_ELEMENT_EXISTS` 的 `endStatus`**

必现页面用 FAIL（默认），可选弹窗要写 PASS。

校验器也加了一条提示：elseSteps 空着又没写 endStatus 时提醒一句。
**这条只提示不打回**——空 elseSteps + 默认 FAIL 对必现页面是完全正确的写法，
打回就是在否定你自己的流程。

  - 把 `toJava` 换回 `asText()` → **3 条立刻变红**（嵌套一层、嵌套两层、标量类型）
  - 把文案变量的放行去掉 → **1 条变红**

没有范例的话，这次改动只剩提示词那三段。

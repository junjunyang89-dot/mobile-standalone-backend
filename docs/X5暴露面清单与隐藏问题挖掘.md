## 三、「能不能试试」——能,但要用对方法

### 在你们自己的设备上,一定全绿

X5 白屏的触发条件是「机型 × 内核版本」,而内核是运行时下载的。
你们几台测试机的组合空间,跟用户的差几个数量级。**在手头设备上跑一百遍也碰不到。**

### 正确的形态

1. 给上面那批**还在 X5 的高风险页面**各配一条流程,页面打开后加一步 `ASSERT_H5_RENDERED`
2. **丢到云真机跑几十个机型** —— 这是唯一能碰到问题机型的办法。
   腾讯 WeTest 尤其对口:X5 就是腾讯的,机型覆盖也最全
3. 每次执行**记录这台机器的 TBS 内核版本**(debug 面板里的 `tv_tbs_info`,零代码改动就能读)

这样得到的是一张「机型 × 内核版本 × 页面」的矩阵,哪一格白屏一目了然。

### 顺带,这批流程还有第二个作用

**卡住回归。** 以后有新页面又用了 X5、或者某个页面从 sysweb 退回 X5,能被抓到——
而现在这种变化是悄悄发生的。

## 四、同一类隐藏问题,还挖到这些

X5 白屏的特征是:**不抛异常、只在部分环境出现、现有断言抓不到**。
按这个特征去翻,找到下面几类。

### 1. 服务端开关 = 一半分支从来没人走过 ⚠️ 最值得看

`MY_TAB_SYS_WEB_SWITCH` 由服务端下发,决定我的页面用哪个内核,本地默认 `true`(系统内核)。

**问题是:你们测的时候,开关是什么状态?** 大概率一直是默认值。
服务端哪天关掉,我的页面回到 X5——**那条路径没人走过**。

而这类开关一共 **7 个**:

```
MY_TAB_SYS_WEB_SWITCH          我的页面用哪个 WebView
DATA_DL_TAB_HIGHLIGHT_SWITCH   DL 数据页高光入口
DATA_DL_TAB_WEEKLY_SWITCH      DL 数据页周报
DISCOVERY_DEADLOCK_SWITCH      发现-Deadlock 赛后数据
DISCOVERY_VIDEO_TRACE_SWITCH   阿里视频单点追查
DOTA2_DATA_SWITCH_DIALOG       Dota2 授权隐私弹窗
SHOW_THEME_SWITCH_GUIDE_DIALOG 主题切换引导
```

**每一个都是一条分叉,而测试通常只走默认那条。**
这比 X5 更隐蔽——X5 至少白屏看得见,开关的另一半分支是压根没被执行过的代码。

建议:把开关状态做成执行参数,同一批用例跑两遍(开/关)。
这件事平台能支持——环境变量已经有了。

### 2. 结构性重复:6 对几乎逐行相同的实现

迁移的代价是现在有两套并行实现:

| X5 那份 | sysweb 那份 |
| --- | --- |
| `web/jsbridge/PWJsBridgeHandler.kt`(775 行) | `sysweb/jsbridge/PWJsBridgeHandler.kt`(775 行) |
| `web/tbs/view/PWx5WebView.kt` | `sysweb/PWWebView.kt` |
| `web/tbs/client/PWx5WebViewClient.kt` | `sysweb/client/PWWebViewClient.kt` |
| `web/tbs/client/PWx5WebChromeClient.kt` | `sysweb/client/PWWebChromeClient.kt` |
| `web/tbs/PWx5JavascriptInterface.kt` | `sysweb/interfaces/PWJavascriptInterface.kt` |
| `util/CaptureWebUtils.kt` | `util/CaptureSysWebUtils.kt` |

**今天还没漂**——我逐个比过:两份 JSBridge 支持的方法集**完全一致**(各 23 个),
WebView settings 也基本一致。

但每一对都是一个「改一份忘一份」的机会,而漂移的表现是
**「某些页面有这个功能,某些没有」,不报错**。

可测:**同一个 JSBridge 方法,在 X5 页面和 sysweb 页面上行为应当一致。**
不一致就是有一份没跟上。这是个硬判据。

## 五、我查过、但**不成立**的(免得你们白费功夫)

| 怀疑 | 结论 |
| --- | --- |
| 迁到系统 WebView 后 cookie 丢失(两套 cookie jar) | **不成立**。`PWx5CookieManager` 里同时调了 `PWCookieManager`,两边都同步 ✓ |
| JSBridge 没有来源校验,任意页面能调原生 | **不成立**。两份 handler 入口都有 `PWWebUrlManager.isInWhiteList(webView?.url)` ✓ |
| 大量空 catch 吞异常 | **不成立**。全仓只有 1 处 ✓ |
| 两套实现已经漂移 | **暂不成立**。方法集和 settings 目前一致,风险是将来 |

## 六、建议的动作,按性价比排

1. **先给钱包 / 支付 / 商城配 `ASSERT_H5_RENDERED` 流程** —— 这几个还在 X5,而且出事最贵
2. **执行时记录 TBS 内核版本** —— 读 debug 面板现成文本,零代码改动
3. **上云真机跑这批流程** —— 唯一能碰到问题机型的办法
4. **服务端开关的另一半分支,至少各跑一遍** —— 7 个开关,比 X5 更隐蔽
5. **加一条仓库检查:X5 入口数只许减不许增** —— 防止新页面又用 X5

第 5 条可以做成脚本挂进你们的构建,几十行的事。

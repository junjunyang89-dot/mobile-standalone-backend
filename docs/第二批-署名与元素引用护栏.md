# 第二批:署名 + 元素引用护栏

> 这两条是"再开放给 50 人心里有底"的最低配:
> **谁改的查得到**,**改了会不会炸别人挡得住**。

---

## 一、元素引用护栏(C)

### 原先的样子

流程引用元素是**按英文名晚绑定**的(步骤里只存 `elementKey`,不写死 xpath)。而元素这一侧:

- `UiElementService:153` 可以随意改 `nameEn`,**零引用检查**
- `UiElementService:185` 删除是裸 `deleteById`,**零引用检查**

而 `UiPageService.delete` 为了防止的**正是这件事**,它的注释已经把后果写清楚了:

> 流程里引用它们的步骤会集体失效——现象是执行时「找不到元素」,没人会联想到是有人删了个页面

**页面层挡住了,元素层没挡。** 而元素才是被直接引用的那一层。

### 改成什么样

删除和改名之前都会扫一遍同应用同平台的流程,有引用就拒绝,并报出**是哪几条流程**:

```
元素「btn_login」还有 7 条流程在引用,不能删除:登录-手机号、
商城-下单、我的-资料 等 7 条。流程按英文名引用元素,删除之后这些流程
执行时会报「找不到元素」。请先改这些流程,或把元素状态改成 DEPRECATED 停用而不是删掉
```

最后半句是刻意加的:**大多数时候人想要的是"停用",不是"删除"**,但界面上只有删除按钮时人就会去删。

### 扫描逻辑单独提成了纯工具

`util/FlowStepScanner`——原先这套整树扫描是 `UiFlowService` 里的私有方法,
提出来是为了让删除/改名复用同一份逻辑,顺便**能单测**。

它守的是两个方向相反的错,而且后者严重得多:

| | 后果 |
| --- | --- |
| **假命中** | 一个其实没人用的元素删不掉,报错说"有 3 条流程在用"却对不上——烦人 |
| **假放过** | 漏掉分支里的引用,删掉之后别人几十条流程下一次跑全红——要命 |

所以两件事都做了:

- **不用字符串 `contains`**——那会把 `btn_ok_cancel` 算成 `btn_ok` 的引用,
  也会把备注里提一句"等 btn_login 出现"算成引用
- **整树扫,不逐层解析**——步骤结构嵌套多变(IF 分支、循环、竞速、组件调用),
  逐层解析加一个新关键字就漏一处;按字段名整树扫,新关键字只要还叫 `elementKey` 就自动覆盖

### 一个特意处理的口子

`elementKeys()` 对脏 JSON 返回**空集**,于是"真没引用"和"没扫出来"长得一样。
把后者当成前者然后放行删除,正是这道护栏要防的事。

所以另外给了 `isParsable()`,而 `assertNotReferenced` 会把扫不动的流程**单独列出来并拒绝操作**:

```
有 2 条流程的步骤解析不了,无法确认是否引用了元素「btn_x」:...
为安全起见本次删除已取消——把「没扫出来」当成「没人用」放过去,正是这道检查要防的事
```

同理,**查流程列表失败时也是拒绝而不是放行**——否则"数据库抖了一下"就等于"没人在用"。

## 二、署名(A)

### 原先的样子

四张表都有 `created_by` 列,但:

- **服务端从不写它**。`UiFlowService.create` 兜底了 catalog / environment / enabled / sortOrder 等七八个字段,**唯独没有 createdBy**——列恒为 NULL
- **值只能来自请求体**,也就是**客户端可以填任何名字**。客户端是 Electron 打包分发的,
  打开 DevTools 或直接 curl 就能写别人的名字进去,而这种伪造没有任何痕迹

> 这是比"没有署名"更糟的状态:**列存在但全是 NULL,看的人会以为这功能做了。**

### 改成什么样

新增 `auth/CurrentUser`,身份取自 `AuthFilter` 放进 request 的那个**已验证过的**用户。
`UiFlowService.create` 和 `UiElementService.create` 里**服务端盖章,覆盖请求体里传进来的值**。

两个设计取舍:

**用 `RequestContextHolder` 而不是到处传 `HttpServletRequest`。**
要盖章的地方在 service 层,而 service 方法签名里塞一个 `HttpServletRequest`
会让它没法从定时任务、组件复制这些非 HTTP 路径调用。

**取不到登录人时留 `null`,不编名字。** 那说明这次调用不是人点的(定时任务、启动初始化)。
另外给了 `nameOr(fallback)` 让调用方自己决定兜底值——
"谁都查不到"和"系统自己建的"是两件事,混成同一个值以后就分不开了。

### mapper 不用改

`UiFlowMapper.xml` / `UiElementMapper.xml` 的 `<result>` 映射和 INSERT 语句**本来就带 `created_by`**,
只是从来没有值传进去。所以这一半是零 SQL 改动。

## 三、`updated_by` 这半边绕不开数据库

"谁建的"现在能查了,**"谁改的"还查不到**——`updated_by` 全仓一处都没有,列也没有。

而 50 人共用一个元素库和流程库,天天发生的是**改**不是**建**。所以这半边其实更重要。

我写了迁移文件放在 `src/main/resources/db/migration_add_updated_by.sql`,**没有执行**:
它是 DDL,什么时候加该你定。幂等的(判 `information_schema`,重复跑不报错)。

文件末尾列了跑完之后还要做的 4 步代码改动。**第 3 步是关键**:

> 只加列不盖章的话,列永远是 NULL,而「列存在但全是 NULL」比「没有这列」更容易骗人
> ——看的人会以为这功能做了。`created_by` 原先就正是这个状态。

要我把那 4 步也做掉吗?做完你直接跑 SQL 就齐了。

## 四、验证

- **519 个源文件真实编译通过**,0 错误
- 全量 **1490 个单测**(本批新增 14):1455 通过、**13 失败**——那 13 条是原有问题,与本次无关
- `FlowStepScanner` **14 个单测全过**

### 反向验证:逐条退回,看测试抓不抓得到

| 退回什么 | 结果 |
| --- | --- |
| 改成字符串 `contains`(`btn_ok_cancel` 会被算成 `btn_ok`) | **2 条红** ✅ |
| 不递归子字段(漏掉 IF 分支里的引用) | **3 条红** ✅ |
| 不遍历数组(漏掉整个步骤列表) | **10 条红** ✅ |
| 脏 JSON 当成可解析(把"没扫出来"当成"没人用") | **红** ✅ |
| 非文本值也算引用(`elementKey: 123`) | **红** ✅ |

### 我写错又改掉的一处

一开始给 `UiFlowMapper` 加了 `@Lazy`,注释里还写了"防止循环依赖"。

查下来**两个都不对**:`UiFlowService` 只注入 mapper,压根没有循环依赖;
而且 `@Lazy` 加在 `@RequiredArgsConstructor` 的 `private final` 字段上**默认不生效**
(需要 `lombok.config` 配 `copyableAnnotations`,你们没有这个文件)。

去掉了,注释也改成了实际情况。**一条解释错误原因的注释,比没有注释更容易误导下一个人。**

## 七、剩下的清单(原文档第二节还剩这些)

| | 问题 | 要不要动数据库 |
| --- | --- | --- |
| **B** | 并发编辑静默覆盖(无乐观锁) | 要 |
| **D** | 零操作留痕 + 全部硬删 | 要 |
| **E** | 定时测试计划绕过设备池,静默丢弃 | 不要 |
| **F** | 僵尸占用被抢占但老线程不杀 | 不要 |
| **G** | 元素采集完全不加锁(最高频路径) | 不要 |
| **H** | 排队超时 30min < 借用上限 2h | **产品取舍,等你定** |
| **I** | 流程执行不传 environment 默认打生产 | 不要 |
| **J** | 多节点会让设备锁失效(启动断言) | 不要 |

按"不碰数据库 + 影响面大"排,下一个我建议 **E 或 G**:

- **E** 是无人值守回归的根本——现在 6 台设备被占满时,定时计划**几乎每次都被静默丢弃**,
  任务停在 PENDING 既不在队列也没人重试,而通过率报表看不出异常
- **G** 是最高频的交互路径(50 人天天点选元素),现在人在点选时调度器**看不到设备被占**,
  3 秒内就可能把任务派到同一台手机上

**I 和 J 都是一小时量级**,可以顺手带上。

# 工程记忆存储方案（最优解）

## 分层（不要只存一整段聊天）

| 层 | 存什么 | 表 / 位置 |
|----|--------|-----------|
| **时间线摘要（主）** | 决策、约定、变更、坑点 | `project_engineering_memory` |
| **完整对话（按需）** | 某次会话 messages JSON | 已有 `agent_conversations` |
| **原则长文** | 设计说明、对接文档 | `docs/*.md` + Git |

调优时：**先查工程记忆 + 文档**，需要细节再拉会话。

## 表结构

见 `src/main/resources/db/schema_engineering_memory.sql`。

`mem_type`：

- `DECISION` 架构/产品决策  
- `CONVENTION` 约定（catalog、短流程等）  
- `CHANGE` 已落地改动  
- `PITFALL` 坑与规避  
- `CONTEXT` 背景说明  

## API（context-path 一般为 `/api`）

```http
GET  /api/engineering-memory?q=回归&tag=ui-flows&type=DECISION&limit=50
GET  /api/engineering-memory/summary
POST /api/engineering-memory
Content-Type: application/json

{
  "memType": "CHANGE",
  "title": "某某调整",
  "body": "做了什么、为什么、影响面",
  "tags": "ui-flows,online-regression",
  "source": "cursor-chat",
  "sessionRef": "可选会话id",
  "createdBy": "yangjun"
}
```

启动后端时会自动建表；若库为空会写入本轮「线上回归统一流程编排」相关种子。

## 协作习惯

1. 重要结论落地后，追加一条记忆（你或 Agent 调 POST）。  
2. 新开 Cursor 对话时：先 `GET /engineering-memory?q=关键词` 或让 Agent 读本文件。  
3. 整段闲聊**不要**默认入库；确需留档再写入 `agent_conversations`。

# 执行日志数据来源说明

本文档说明「任务详情」里展示的**执行日志**（executionLog）是从哪里来的、如何存储、如何返回给前端。

---

## 一、日志是什么

执行日志是**功能体验基础质量测试**（如登录测试）在**执行过程中**按步骤写入的一条条记录，例如：

- 开始测试
- 获取执行步骤、应用信息解析完成
- 设备环境就绪、启动应用程序、成功启动应用程序
- 主界面就绪、开始登录流程
- 检测温馨提示 / 打开侧边栏、判断登录状态、点击登录入口
- 手机号输入框已出现、输入手机号、勾选协议并发送验证码
- 验证码输入框已出现、输入验证码
- 执行完成并截图、报告已生成、测试服务执行完毕

每条包含：步骤名（step）、级别（level）、状态（status）、说明（message）、可选截图路径（screenshotPath/screenshotUrl）等。

---

## 二、日志从哪里来（数据源）

| 环节 | 位置 | 说明 |
|------|------|------|
| **1. 产生** | `LoginTestService.executeLoginTest()` | 登录测试执行时，在代码里按步骤 `executionLog.add(ExecutionLogEntryDto.success(...))` 或 `fail(...)`，**实时**往内存里的一个 `List<ExecutionLogEntryDto>` 里追加。 |
| **2. 返回** | `LoginTestService` → `FunctionalTestExecutionResult` | 方法最后 `return new FunctionalTestExecutionResult(reportPath, executionLog, variables)`，把整份 **executionLog** 列表交给上层。 |
| **3. 调用方** | `TestScriptExecutor.executeFunctionalQualityTest()` | 若是「完美世界电竞」登录场景，会调用 `loginTestService.executeLoginTest(task, device)`，拿到的 **FunctionalTestExecutionResult** 里就带有这份 executionLog。 |
| **4. 写入库** | `TaskService`（执行任务的 run 逻辑） | 拿到 `FunctionalTestExecutionResult` 后，把 `result.getExecutionLog()` 用 **JSON 序列化**成字符串，调用 `execution.setExecutionLog(jsonString)`，再 `executionMapper.update(execution)`，写入表 **task_executions** 的 **execution_log** 列（TEXT）。 |
| **5. 失败时** | `TaskService` catch 块 | 若执行中途抛异常，会通过 `loginTestService.getAndClearExecutionLog()` 取出**已产生的部分日志**，同样序列化后写入 **execution_log**，便于排查。 |

**结论：**  
- 日志数据源 = **本机在执行「功能体验基础质量测试」时，由 `LoginTestService` 在内存里按步骤生成**。  
- 不是从文件、不是从外部系统、也不是从别的表“汇总”来的，就是**当次任务执行过程中代码打出来的步骤记录**。

---

## 三、存储位置

| 存储 | 说明 |
|------|------|
| **表** | `task_executions` |
| **列** | `execution_log`（TEXT，可为 NULL） |
| **格式** | JSON 数组字符串，元素为 `ExecutionLogEntryDto`（step、level、status、message、selector、timestamp、screenshotPath 等）。 |

一次任务执行对应一条 `task_executions` 记录；该记录里的 **execution_log** 即**当次执行**的完整步骤日志。

---

## 四、前端从哪里拿到日志

| 接口 | 数据来源 |
|------|----------|
| **GET** `{baseUrl}/functional-test/tasks/{id}`（任务详情） | 查 `task_executions` 表该任务**最近一次执行**（`findByTaskIdOrderByStartTimeDesc`），取这条记录的 **execution_log** 列，反序列化成 `List<ExecutionLogEntryDto>`，填充每步的 **screenshotUrl** 后，放在响应的 **executionLog** 字段里。 |
| **GET** `{baseUrl}/functional-test/tasks/{id}/execution-log` | 同上，查最近一次执行的 **execution_log** 列，反序列化后直接返回该列表。 |

即：前端拿到的日志 = **数据库表 task_executions 中，该任务最近一次执行记录里的 execution_log 列**，由后端反序列化并补全 screenshotUrl 后返回。

---

## 五、小结

- **谁产生**：`LoginTestService` 在跑登录测试时，在内存里按步骤写入。  
- **谁入库**：`TaskService` 把该列表 JSON 序列化后写入 **task_executions.execution_log**。  
- **谁读出**：任务详情、执行日志两个接口从 **task_executions** 取**最近一次执行**的 **execution_log**，反序列化后返回。  

因此，你看到的「执行日志」= **当次任务执行时后端自己打出来的步骤记录，存进 task_executions.execution_log，再通过接口从库里读出来给前端**。

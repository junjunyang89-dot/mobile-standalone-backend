# 性能基础质量测试 - 联调文档

供前端与后端联调时使用，包含：前端需做调整汇总、联调步骤、请求/响应示例、自测检查点、常见问题。

**约定**：`baseUrl` = 后端基址（如 `http://localhost:3000/api`），下文均以 `{baseUrl}` 表示。

---

## 一、前端需要做的调整（汇总）

| 序号 | 调整项 | 说明 |
|------|--------|------|
| 1 | **创建性能任务** | 使用 `POST {baseUrl}/tasks/test`，body 含 `taskType: "PERFORMANCE_BASELINE_TEST"`、`platform`、`deviceId`、`appId`；可选 `config: "{\"traversalMinutes\": 5}"`（执行时长）。 |
| 2 | **任务列表** | 性能任务必须用 `GET {baseUrl}/tasks`（可传 `taskType=PERFORMANCE_BASELINE_TEST`）。**不要**只用 `GET {baseUrl}/functional-test/tasks`，该接口不包含性能任务。 |
| 3 | **测试场景列** | 列表/详情的「测试场景」直接展示接口返回的 `scenarioName`（性能任务后端会填「性能基础质量测试(Android)」等）。 |
| 4 | **运行后状态** | 点击「运行」后**必须轮询** `GET {baseUrl}/tasks/{taskId}`（建议 3～5 秒一次），直到 `status` 不为 `RUNNING`，否则页面会一直显示「已停止」。 |
| 5 | **性能报告** | 报告数据**仅**通过 `GET {baseUrl}/functional-test/tasks/{id}/performance-report` 获取 JSON，不可用 iframe/静态路径。 |
| 6 | **整体评估** | 用返回的 `conclusion`、`issueSummary`（含 `byOperationType`）渲染结论与问题统计。 |
| 7 | **遍历统计** | 用 `traversalDurationMinutes`、`launchCount`、`clickCount`、`swipeCount`、`screenshotTimeline`；截图用 `.../performance-screenshots/{index}`。 |
| 8 | **资源数据** | 用 `resourceSummary`、`resourceSamples` 渲染 CPU/内存/网络/温度 汇总与曲线。 |
| 9 | **操作详情表格** | 用 `operations` 数组，列对应：操作类型(`index`+`actionLabel`)、操作前/后(`screenshotBeforeIndex`/`screenshotAfterIndex` 拼截图 URL)、响应时延(`responseDelayMs`)、完成时延(`completionDelayMs`)、黑白块(`whiteScreenMs`)、维测数据(`cpuAvgDuringStep`/`memoryPssKbDuringStep`)。 |
| 10 | **任务详情/概览** | 继续用 `GET {baseUrl}/functional-test/tasks/{id}/overview`，执行日志用 `executionLog`。 |

---

## 二、联调步骤与接口示例

### 步骤 1：创建性能测试任务

**请求**

```http
POST {baseUrl}/tasks/test
Content-Type: application/json

{
  "taskType": "PERFORMANCE_BASELINE_TEST",
  "platform": "ANDROID",
  "deviceId": "6HJDU20409003857",
  "appId": "dab99b1e-a43d-45cc-b500-4d2da0759e88",
  "config": "{\"traversalMinutes\": 5}"
}
```

**响应 200 示例（节选）**

```json
{
  "id": "task-uuid-xxx",
  "name": "性能基础质量测试",
  "taskType": "PERFORMANCE_BASELINE_TEST",
  "platform": "ANDROID",
  "deviceId": "6HJDU20409003857",
  "appId": "dab99b1e-a43d-45cc-b500-4d2da0759e88",
  "status": "PENDING",
  "scenarioName": "性能基础质量测试(Android)"
}
```

**自测**：返回 200 且带 `id`、`status: PENDING`；`scenarioName` 有值。

---

### 步骤 2：任务列表（含性能任务）

**请求**

```http
GET {baseUrl}/tasks?taskType=PERFORMANCE_BASELINE_TEST&page=1&size=10
```

或不分页：

```http
GET {baseUrl}/tasks?taskType=PERFORMANCE_BASELINE_TEST
```

**响应 200**：分页时为 `{ "content": [...], "totalElements": n, "totalPages": m, "page": 1, "size": 10 }`；不分页时为任务数组。每条任务含 `id`、`name`、`taskType`、`status`、`scenarioName` 等。

**自测**：刚创建的性能任务出现在列表中；`scenarioName` 为「性能基础质量测试(Android)」类文案。

---

### 步骤 3：运行任务

**请求**

```http
POST {baseUrl}/tasks/{taskId}/run
```

**响应 200 示例**

```json
{
  "success": true,
  "message": "任务已开始执行"
}
```

**自测**：返回 200 后，立即请求步骤 4，应看到 `status: "RUNNING"`。

---

### 步骤 4：轮询任务状态（必做）

**请求**（每 3～5 秒一次，直到 status 非 RUNNING）

```http
GET {baseUrl}/tasks/{taskId}
```

**响应 200 示例（运行中）**

```json
{
  "id": "task-uuid-xxx",
  "status": "RUNNING",
  "taskType": "PERFORMANCE_BASELINE_TEST",
  "scenarioName": "性能基础质量测试(Android)"
}
```

**结束轮询**：当 `status` 为 `COMPLETED`、`FAILED` 或 `STOPPED` 时停止轮询，并刷新列表/进入报告页。

**自测**：运行后 5～10 秒内轮询到 `RUNNING`；测试结束后轮询到 `COMPLETED` 或 `FAILED`。

---

### 步骤 6：获取截图（操作前/操作后或时间轴）

**请求**（index 为数字，从 0 起，且 index < screenshotCount）

```http
GET {baseUrl}/functional-test/tasks/{taskId}/performance-screenshots/0
GET {baseUrl}/functional-test/tasks/{taskId}/performance-screenshots/1
```

**响应 200**：body 为图片二进制（Content-Type: image/png），可直接用作 `<img src="上述URL">`。

**响应 404**：任务不存在、非性能任务、或 index 超出最新执行的 screenshotCount。

**自测**：用 `operations[i].screenshotBeforeIndex`、`screenshotAfterIndex` 拼 URL，能正常显示缩略图。

## 三、联调自测检查点

| 检查项 | 预期 |
|--------|------|
| 创建性能任务 | POST /tasks/test 返回 200，列表中出现新任务，测试场景列有「性能基础质量测试(Android)」等。 |
| 运行后状态 | 点击运行后 5～10 秒内（轮询）状态变为「运行中」；结束后变为「已完成」或「失败」。 |
| 不轮询时 | 点击运行后若不轮询，列表仍显示旧状态（如「已停止」），易误判。 |
| 性能报告 | 执行完成后 GET performance-report 返回 200，有 conclusion、operations、resourceSummary、issueSummary。 |
| 操作详情表格 | operations 每行可展示：序号+actionLabel、操作前/后图（用 screenshotBeforeIndex/AfterIndex 拼 URL）、responseDelayMs、completionDelayMs、whiteScreenMs、维测数据。 |
| 截图 | .../performance-screenshots/{index} 返回 200 且为图片；index 来自 operations 或 screenshotTimeline。 |

## 四、常见问题与排查

| 现象 | 可能原因 | 排查/处理 |
|------|----------|-----------|
| 列表里没有性能任务 | 使用了 GET /functional-test/tasks | 改用 GET /api/tasks，并传 taskType=PERFORMANCE_BASELINE_TEST。 |
| 点击运行后一直显示「已停止」 | 未轮询任务状态 | 运行成功后轮询 GET /api/tasks/{id}，每 3～5 秒，直到 status 非 RUNNING。 |
| 性能报告没有数据 / 404 | 把报告当静态路径用（如 iframe） | 必须用 GET .../performance-report 取 JSON，再前端渲染。 |
| 操作详情没有截图 | ① 后端未开截图 ② 前端未用 index 拼 URL | 确认 performance.screenshot-interval-seconds>0；前端用 screenshotBeforeIndex/screenshotAfterIndex 拼 GET .../performance-screenshots/{index}。 |
| 长时测试最后显示「失败」 | result_data 超出数据库字段长度 | 后端执行 db/migration_result_data_mediumtext.sql，将 task_executions.result_data 改为 MEDIUMTEXT。 |
| 创建任务 400 | 缺少必填或格式错误 | 检查 body 含 taskType、platform、deviceId、appId；config 为 JSON 字符串如 "{\"traversalMinutes\": 5}"。 |

## 五、接口速查

| 用途 | 方法 | 路径 |
|------|------|------|
| 创建性能任务 | POST | {baseUrl}/tasks/test |
| 任务列表（含性能） | GET | {baseUrl}/tasks?taskType=PERFORMANCE_BASELINE_TEST&page=1&size=10 |
| 单任务状态 | GET | {baseUrl}/tasks/{id} |
| 运行任务 | POST | {baseUrl}/tasks/{taskId}/run |
| 任务概览（含执行日志） | GET | {baseUrl}/functional-test/tasks/{id}/overview |
| 性能报告 JSON | GET | {baseUrl}/functional-test/tasks/{id}/performance-report |
| 某张截图 | GET | {baseUrl}/functional-test/tasks/{id}/performance-screenshots/{index} |

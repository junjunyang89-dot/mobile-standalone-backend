# 功能基础质量测试 - 场景与前端对接说明

功能基础质量测试已按**场景**区分：启动应用程序、登录、搜索等，并按 **Android / iOS / 鸿蒙** 走不同执行路径。创建任务时需选择「测试场景」，接口与数据有少量新增与变更。

---

## 一、接口变更摘要

| 变更类型 | 说明 |
|----------|------|
| **新增接口** | `GET {baseUrl}/functional-test/scenarios/functional-quality`：仅返回功能基础质量测试下的场景列表（启动应用程序、登录、搜索、**设置**、**设置-我的账号**、**设置-我的兴趣**、**设置-高校认证**），供创建任务时「测试场景」下拉使用。 |
| **场景列表** | `GET {baseUrl}/functional-test/scenarios` 响应中每条场景增加字段 **`scenarioKey`**（`launch_app` / `login` / `search` / **`settings`** / **`settings_account`** / **`settings_interests`** / **`settings_school_cert`**）。 |
| **创建任务** | `POST {baseUrl}/functional-test/tasks` 请求体增加可选字段 **`scenarioKey`**；不传则执行逻辑按原兼容方式。**`settings`** = 设置测试，**`settings_account`** = 设置-我的账号，**`settings_interests`** = 设置-我的兴趣，**`settings_school_cert`** = 设置-高校认证（均需完美世界电竞应用 + Appium）。 |
| **任务详情/列表** | 任务相关响应增加 **`scenarioKey`**、**`scenarioName`**，便于展示（如「设置测试(Android)」「设置-我的账号(iOS)」「设置-高校认证(Android)」）。 |

---

## 二、前端需要调整的数据与调用

### 2.1 创建任务页「测试场景」下拉

- **数据来源（二选一）**  
  - 仅功能场景：`GET {baseUrl}/functional-test/scenarios/functional-quality`  
  - 全部场景：`GET {baseUrl}/functional-test/scenarios`（再按 `taskType === 'FUNCTIONAL_QUALITY_TEST'` 过滤）
- **展示**：用返回的 `name` 做展示（如「启动应用程序(Android)」「登录测试(iOS)」「设置测试(Android/iOS)」「设置-我的账号(Android/iOS)」「设置-我的兴趣(Android/iOS)」「设置-高校认证(Android/iOS)」）；选项的 `platform` 需与当前表单所选「平台类型」一致时再展示或可选。
- **提交创建任务时**：将选中场景的 **`scenarioKey`** 填入请求体 **`scenarioKey`**；若未选场景可传 `null` 或不传。
- **设置测试**：`scenarioKey = settings`；**设置-我的账号**：`scenarioKey = settings_account`；**设置-我的兴趣**：`scenarioKey = settings_interests`；**设置-高校认证**：`scenarioKey = settings_school_cert`。均仅支持完美世界电竞应用 + Appium；执行时若已登录则跳过登录，否则先登录再进入设置页（子场景会再进入对应子页）并截图。

### 2.2 创建任务请求体（POST /functional-test/tasks）

**新增可选字段：**

| 字段 | 类型 | 说明 |
|------|------|------|
| **scenarioKey** | string \| null | 测试场景键：`launch_app`、`login`、`search`、`settings`（设置测试）、`settings_account`（设置-我的账号）、`settings_interests`（设置-我的兴趣）、`settings_school_cert`（设置-高校认证）。不传或 null 时按原逻辑。 |

其余字段不变：taskName、remarks、platform、deviceId、applicationId、config。

### 2.3 任务列表 / 任务详情响应

**新增字段（任务相关接口统一）：**

| 字段 | 类型 | 说明 |
|------|------|------|
| **scenarioKey** | string \| null | 场景键：`launch_app` / `login` / `search` / `settings` / `settings_account` / `settings_interests` / `settings_school_cert`。 |
| **scenarioName** | string \| null | 场景展示名，如「设置测试(Android)」「设置-我的账号(iOS)」「设置-高校认证(Android)」。 |

- 任务列表（如 `GET /functional-test/tasks`）的每项、任务详情（如 `GET /functional-test/tasks/{id}`）的响应中都会带 `scenarioKey`、`scenarioName`。
- **前端展示建议**：在**测试任务列表表格**中增加一列「**测试场景**」，绑定 `scenarioName`（无则显示「-」）；在任务卡片或详情中展示「任务类型 + 场景 + 平台」或直接展示 **scenarioName**，例如：「功能体验基础质量测试 - 启动应用程序(Android)」。

### 2.4 场景列表响应（GET /scenarios 或 /scenarios/functional-quality）

每条场景对象新增字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| **scenarioKey** | string \| null | 场景键，创建任务时传此值给 `scenarioKey`。 |

原有字段 id、name、platform、taskType、description 不变。

---

## 三、场景键与执行逻辑对应关系

| scenarioKey | 含义 | 执行逻辑 |
|-------------|------|----------|
| **launch_app** | 启动应用程序 | 按所选平台（Android/iOS/鸿蒙）启动应用并截图，产出启动相关执行日志。 |
| **login** | 登录 | 当前为完美世界电竞登录流程；若应用不支持登录则走通用步骤并带占位说明。 |
| **search** | 搜索 | 占位实现：启动应用 + 截图 + 「搜索测试(占位)」日志，后续可接入真实搜索步骤。 |
| **settings** | 设置测试 | 若已登录则跳过登录；否则登录 → 侧边栏 → 设置页 → 截图。仅支持完美世界电竞 + Appium。 |
| **settings_account** | 设置-我的账号 | 若已登录则跳过登录；否则登录 → 侧边栏 → 设置页 → 我的账号页 → 截图。仅支持完美世界电竞 + Appium。 |
| **settings_interests** | 设置-我的兴趣 | 若已登录则跳过登录；否则登录 → 侧边栏 → 设置页 → 我的兴趣页 → 截图。仅支持完美世界电竞 + Appium。 |
| **settings_school_cert** | 设置-高校认证 | 若已登录则跳过登录；否则登录 → 侧边栏 → 设置页 → 高校认证页 → 截图。仅支持完美世界电竞 + Appium。 |
| 不传 / null | 默认 | 与之前一致：支持登录则走登录，否则走通用步骤。 |

## 四、前端联调清单（设置测试）

按下面步骤即可完成「设置」场景的联调，无需改其它接口路径。

| 步骤 | 前端要做的事 | 接口/数据 |
|------|----------------|-----------|
| 1 | 创建任务页「测试场景」下拉要能拉出「设置测试(Android)」「设置测试(iOS)」 | 调 `GET {baseUrl}/functional-test/scenarios/functional-quality`，会返回 `scenarioKey: "settings"`、`name: "设置测试(Android)"` / `"设置测试(iOS)"`、`platform` 等 |
| 2 | 用户选「设置测试」时，提交创建任务请求体里带 **scenarioKey: "settings"** | `POST {baseUrl}/functional-test/tasks`  body: `{ ..., scenarioKey: "settings", platform: "ANDROID" 或 "IOS", deviceId, applicationId }` |
| 3 | 任务列表/详情里能区分「设置」任务 | 响应里会有 `scenarioKey: "settings"`、`scenarioName: "设置测试(Android)"` 等，用 `scenarioName` 或「设置测试」标签展示即可 |
| 4 | 运行任务、查看执行日志/截图 | 与现有「功能基础质量」一致：点运行 → 轮询 `GET {baseUrl}/functional-test/tasks/{id}` 或 overview → 用 `executionLog` 展示步骤、用 `{baseUrl}/functional-test/tasks/{id}/screenshot` 展示最终截图 |

**前置条件（后端/环境）：**

- 后端配置 `appium.enabled: true`，Appium Server 已启动且设备已连接。
- 所选应用为**完美世界电竞**（包名含 `steam.esports`），在「选择应用」里选该应用即可。

**可选：** 若希望只在「选的是完美世界电竞应用」时展示「设置测试」选项，可据应用包名或后端场景列表的 `platform` 做前端过滤；不做过滤也可以，后端会在执行时校验，不支持会返回明确错误信息。

**若「设置」任务运行后没有走设置逻辑（例如只走了登录或通用步骤）：**

1. 确认创建任务时请求体里带了 **`scenarioKey: "settings"`**（或 `"Settings"`，后端会规范为小写）。
2. 创建成功后，响应或任务详情里应有 **`scenarioKey: "settings"`**、**`scenarioName: "设置测试(Android)"** 等；若无，说明创建时未传或未保存，需检查前端是否把「测试场景」选中的值传给 `scenarioKey`。
3. 后端执行时按 `task.scenarioKey === "settings"` 才会进入设置测试；若库里该任务 `scenario_key` 为空，会按默认逻辑（登录或通用）执行。

---

## 五、数据库与兼容性

- 任务表已增加 **scenario_key** 列（可为空）。旧任务该列为空，接口仍会返回 `scenarioKey`/`scenarioName` 为 null，前端按「无场景」展示即可。
- 不传 `scenarioKey` 的创建请求行为与改版前一致，无需强制选场景。

按上述说明调整后，创建任务时可明确选择「启动应用程序」「登录」「搜索」「设置」等场景，列表与详情也能展示「这个任务具体要做什么」。

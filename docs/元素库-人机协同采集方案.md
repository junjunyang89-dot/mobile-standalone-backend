# 元素库 · 人机协同采集方案（AI 对话专用）

> **用途**：把本文整份（或「附录 A：AI 开场指令」）贴进 AI 对话，再按页投喂 page source / 截图，由 AI 增量产出可入库元素。  
> **入库目标**：本地平台「元素库」`ui_elements`（前端菜单：元素库）。  
> **关联旧文档**：`APPIUM_AND_ELEMENT_MAINTENANCE.md`、`docs/ELEMENT_STORAGE_AND_READ.md`（偏 `page_objects`）；本方案以行级 **UiElement** 为准。

---

## 1. 目标

- **人导航、AI 记账**：你手动从「未登录」开始逐页操作；AI 解析本页并产出候选元素。
- **一页一轮**：每进一页（或弹一层）采集一次，不攒到最后。
- **审核后入库**：AI 只出草稿；你勾选后再写入元素库。
- **平台分开**：Android / iOS 各建记录；`nameEn` 尽量同名，locator 可不同。

元素维护工程大时，用「增量账本」拆解，比一次性全量定位可控得多。

---

## 2. 角色

| 角色 | 职责 |
|------|------|
| 你 | 连设备、启 App、手动操作、导出 XML/截图、定本页范围、审核并写入元素库 |
| AI | 解析 page source、选 locator、起名、填表、维护已采账本、标注风险 |
| 元素库 | 最终存储；自动化流程用 `nameEn` 引用 |

---

## 3. 元素库字段对齐（入库必填）

对应实体 `UiElement` / 表 `ui_elements`（**不新建表**；双源同表对比）：

| 字段 | 说明 | 本方案约定 |
|------|------|------------|
| `catalog` | AUTOMATION / ONLINE / SHARED | 默认 **SHARED**（两边共用） |
| `appId` | 应用 ID | 会话开头固定，之后可省略 |
| `platform` | ANDROID / IOS / … | 当前设备平台 |
| `nameZh` | 中文名 | 如「登录按钮」 |
| `nameEn` | 流程引用 key | 如 `login_btn`（稳定、不随意改） |
| `moduleTag` | 模块分组 | 如「设置」（展示分组） |
| `pageId` | 页面 ID | 如 `P08_MINE_SETTINGS`（与账本 pageId 对齐） |
| `source` | 来源 | 人机协同填 **HUMAN_AI**；源码解析为 SOURCE_CODE |
| `status` | 选用状态 | 采集默认 **CANDIDATE**；审核选用后改 **ACTIVE** |
| `description` | 描述 | 出现条件、易变点 |
| `visualHint` | 视觉说明 | 如「左上角三横线汉堡」，方便人眼对上截图；检索可搜 |
| `locatorType` | id / xpath / text / accessibilityId / className / name / other | 见第 8 节优先级 |
| `locatorValue` | 定位值 | 具体表达式 |
| `previewImage` | 预览图 | 可选 |
| `defaultTimeoutSec` | 默认超时 | 可选，默认 10 |
| `enabled` | 是否启用 | 默认 true |

唯一性：同一 `appId + platform + nameEn + source` 不重复（人机与源码可各存一行对比）。  
执行解析优先取 `status=ACTIVE`，同名多源时 **HUMAN_AI** 优先。

---

## 4. 一次性准备

1. 选定先做平台（建议先 **Android**，再 iOS 复用 `nameEn`）。
2. Appium Server 已启动；Inspector 或会话可导出 page source。
3. App **清数据 / 重装**，从未登录态冷启动。
4. 在对话中声明常量：
   - `appId`
   - `platform`（ANDROID / IOS）
   - `catalog` = SHARED
5. 会话信息发一次即可：
   - Appium server 地址
   - platformName、deviceName / udid
   - Android：`appPackage` / `appActivity`
   - iOS：`bundleId`

## 6. 标准循环

```
你操作到目标页
  → 导出 page source（+ 可选截图）
  → 按「投喂模板」发给 AI
  → AI 产出候选表
  → 你审核（可让 AI 改）
  → 写入元素库
  → 账本勾选本页完成
  → 下一页
```

单页预期：**3～8 分钟**（含操作 + 导出 + 审核）。

## 8. Locator 策略（AI 必须遵守）

### Android 优先级

1. `resource-id` → `locatorType=id`
2. `content-desc` → `accessibilityId`
3. 稳定文案 → `text`
4. **短相对 xpath**
5. 禁止：超长绝对 xpath、纯坐标（除非你点名）

### iOS 优先级

1. accessibility id / name → `accessibilityId` 或 `name`
2. label
3. xpath

### 默认不进库

- 无业务语义的布局容器（View / FrameLayout 等）
- 一次性动画节点
- 高度依赖索引的脆弱路径（如 `ViewGroup[3]/...`）
- 装饰性图标（除非是唯一可点入口）

---

## 9. 命名约定

### nameEn

```
{模块}_{控件}_{语义}
```

示例：

- `login_btn` / `login_phone_input` / `login_code_input`
- `home_tab_mine` / `mine_settings_entry`

规则：

- 小写 + 下划线
- Android / iOS **同名**（仅 locator 不同）
- 已入库的 `nameEn` **不改名**，只改 locator
- 不与同 app + platform 已有 key 冲突

### nameZh / moduleTag

- `nameZh`：业务可读，如「登录按钮」
- `moduleTag`：与页面一致，如「登录页」「首页」「我的」

## 10. AI 产出格式（固定）

每轮输出一张表（可再附 JSON）：

| 建议入库 | nameZh | nameEn | moduleTag | locatorType | locatorValue | description | 风险 |
|----------|--------|--------|-----------|-------------|--------------|-------------|------|
| 是 | 登录按钮 | login_btn | 登录页 | id | com.xxx:id/btn_login | 主登录 CTA | 无 |

并同步更新 **账本**：

| pageId | pageName | Android | iOS | 元素数 | 状态 |
|--------|----------|---------|-----|--------|------|
| P05 | 登录填写页 | ✅ | ⬜ | 6 | 已产出待入库 |

说明：

- `建议入库=否` 的行可列出供参考，默认不入库。
- 风险示例：纯 text 易变、绝对 xpath 脆弱、多页可能撞车。

可选 JSON（便于以后批量 `POST /api/ui-elements`）：

```json
{
  "catalog": "SHARED",
  "appId": "your-app-id",
  "platform": "ANDROID",
  "nameZh": "登录按钮",
  "nameEn": "login_btn",
  "moduleTag": "登录页",
  "description": "主登录 CTA",
  "locatorType": "id",
  "locatorValue": "com.xxx:id/btn_login",
  "defaultTimeoutSec": 10,
  "enabled": true
}
```

## 11. 双机策略

| 阶段 | 做法 |
|------|------|
| 第 1 台 | 按路线图完整走，建立 `nameEn` 主表 |
| 第 2 台 | 同一 `pageId` 再采；复用 `nameZh` / `nameEn` / `moduleTag`，只换 `platform` + locator |
| 差异 | 某端没有的控件：该端不建，或建后 `enabled=false` 并备注 |

两台可交替：A 机一页 → AI 记完 → B 机同页再发 XML。

---

## 12. 质量门禁（入库前）

1. Inspector / 会话中能 Find 到。
2. 不是过宽、易撞车的 text（除非本页唯一且稳定）。
3. `nameEn` 不与库内同平台重复。
4. `moduleTag` 与路线图一致。
5. （可选）同页抽 2～3 个关键元素点验。

---

## 13. 入库方式

**现阶段（推荐）**：打开平台「元素库」→ 新增 → 按 AI 表格粘贴。

**半自动（后续）**：勾选后批量调 `POST /api/ui-elements`。

**不做**：无人值守全自动写库。

## 14. 站内点选采集（已实现）

平台「元素库」页提供 **真机点选**，无需再只靠外部 Appium Inspector 对图猜元素。

### 14.1 检索增强

- 关键词可搜：中英文名、描述、pageId、**locator_value**、moduleTag、**visual_hint（视觉说明）**
- 字段 `visual_hint`：人眼对上截图，如「左上角三横线汉堡」
- 迁移：`src/main/resources/db/migration_ui_element_visual_hint.sql`

### 14.2 真机点选流程

1. 元素库 → **真机点选** → 选已连接设备 → **刷新截图**
2. 在截图上点击目标控件（如汉堡菜单）
3. 右侧展示命中候选（优先 resource-id → content-desc → 短 xpath）
4. 若已匹配库内元素 → **选用已匹配**；否则改名后 **新建候选** / **新建并选用**

### 14.3 API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/devices/{id}/inspect/snapshot` | 截图 URL + 窗口宽高 |
| POST | `/devices/{id}/inspect/hit-test` | body: `{ xRatio, yRatio, appId? }` → 候选 + 已匹配元素 |

Android：截图走 ADB，page source 优先 Appium 会话，否则 `uiautomator dump`。  
iOS：需已有 Appium/WDA 会话（否则 page source 可能失败）。

原则：**点选入库仍需人确认**；不做无人值守全自动写库。

# 周改动漏测看板

白盒（本地多仓 `git diff base...head`）+ 黑盒（手写必测清单 / 人工标记），与「发版文档」互补。

| 页面 | 看什么 |
|------|--------|
| 发版文档 | 需求备注里的分支名、SQL、配置（上线清单） |
| 周改动漏测 | 仓库真实文件改动、模块风险、清单未覆盖、SQL 备注对照 |

## 用法

1. 本机 clone 各项目，fetch 本周分支。
2. 打开 **其他 → 周改动漏测**，配置本地路径 + 基线（如 `master`）+ 本周分支。
3. （可选）「必测清单」粘贴手写用例关键字；「发版文档带入」预览抽取分支/DB 备注。
4. 点 **扫描改动**，在结果里标记：必测 / 已覆盖 / 可忽略。

## API

- `GET /api/change-review/ping`
- `POST /api/change-review/diff`
- `POST /api/change-review/import-branches`

## 配置（application.yml）

```yaml
change-review:
  enabled: true
  allowed-roots: []   # 非空则限制仓库必须在这些根目录下
  allow-fetch: false
  timeout-sec: 90
```

标记与项目配置默认存在浏览器 `localStorage`。

# 设备管理接口说明（给前端）

用于「设备管理」页的**设备列表**展示与操作，以及**首页**已连接设备统计。后端 `context-path` 为 `/api`，基址示例：`http://localhost:3000/api`。

---

## 首页：已连接设备统计（推荐首页首屏调用）

用于首页「已连接设备」卡片数字、以及「设备状态」表格（设备名称、平台、状态）。**一次请求**即可拿到总数、各平台数量与设备列表。

| 项目 | 值 |
|------|-----|
| **方法** | `GET` |
| **URL** | `{baseUrl}/devices/connected-summary` |
| **示例** | `http://localhost:3000/api/devices/connected-summary` |

**请求参数：** 无。

**响应：** `200`，JSON 对象。

| 字段 | 类型 | 说明 |
|------|------|------|
| **totalConnected** | number | 已连接设备总数（对应「已连接设备」卡片） |
| **androidCount** | number | 已连接 Android 数量 |
| **iosCount** | number | 已连接 iOS 数量 |
| **harmonyosCount** | number | 已连接 HarmonyOS 数量 |
| **devices** | array | 已连接设备列表，用于「设备状态」表格 |

**devices** 每项字段：`id`、`name`、`platform`（`ANDROID`/`IOS`/`HARMONYOS`）、`version`、`status`（`CONNECTED`）、`lastSeen` 等，与「获取设备列表」单条结构一致。

**响应示例：**

```json
{
  "totalConnected": 2,
  "androidCount": 1,
  "iosCount": 1,
  "harmonyosCount": 0,
  "devices": [
    { "id": "6HJDU20409003857", "name": "SEA_AL10", "platform": "ANDROID", "version": "10", "status": "CONNECTED", "lastSeen": "2026-02-03T18:30:00" },
    { "id": "00008030-001234567890001E", "name": "iPhone", "platform": "IOS", "version": "17.0", "status": "CONNECTED", "lastSeen": "2026-02-03T18:30:00" }
  ]
}
```

**前端用法建议：**

- 首页加载时调用 `GET {baseUrl}/devices/connected-summary`。
- 「已连接设备」卡片显示 `totalConnected`；若需展示「Android x 台 / iOS x 台」可用 `androidCount`、`iosCount`。
- 「设备状态」表格数据源用 `devices`，列：设备名称（`name`）、平台（`platform`）、状态（`status` 可展示为「已连接」）。
- 用户**点击「已连接设备」总量或表格中某台设备**时，请求下方「设备详情」接口，展示该设备的电量、安装应用、以及（iOS）详细设备信息。

---

## 设备详情（点击设备后展示）

用于前端点击某台设备后，展示**设备名称、电量、已安装应用**；**iOS 设备**额外返回与 iMazing 概览类似的详细数据（型号、序列号、UDID、运营商、储存等）。

| 项目 | 值 |
|------|-----|
| **方法** | `GET` |
| **URL** | `{baseUrl}/devices/{deviceId}/detail` |
| **示例** | `http://localhost:3000/api/devices/00008150-0006189C210A401C/detail` |

**路径参数：** `deviceId` 为设备 ID（与 `connected-summary` 或设备列表中的 `id` 一致）。

**响应：** `200` 为成功，`404` 为设备不存在或无效。

**响应体字段：**

| 字段 | 类型 | 说明 |
|------|------|------|
| **id** | string | 设备 ID |
| **name** | string | 设备名称 |
| **platform** | string | `ANDROID` / `IOS` / `HARMONYOS` |
| **version** | string | 系统版本 |
| **status** | string | `CONNECTED` / `DISCONNECTED` |
| **lastSeen** | string | 最后可见时间（ISO） |
| **batteryLevel** | number \| null | 电量百分比 0–100，无法获取时为 `null` |
| **installedApplications** | array | 已安装应用列表 |
| **iosDetail** | object | **仅 iOS**：ideviceinfo 解析后的键值对，用于表格/列表展示 |
| **iosDetailRaw** | string | **仅 iOS**：ideviceinfo 完整原始输出，前端可直接用 `<pre>` 完整展示，确保不遗漏任何一行 |
| **androidDetail** | object | **仅 Android/HarmonyOS**：系统、硬件、电池、存储、网络、安全等分层信息，见下表 |
| **androidDetailRaw** | string | **仅 Android/HarmonyOS**：getprop + dumpsys battery 完整原始输出，前端可直接用 `<pre>` 完整展示 |

**installedApplications** 每项：

| 字段 | 类型 | 说明 |
|------|------|------|
| name | string | 应用名称 |
| packageName | string | 包名（Android）/ Bundle ID（iOS） |
| version | string | 应用版本 |

**iosDetail**（仅 iOS 有）：键值对形式，常见键包括（具体以设备实际返回为准）：

- **DeviceName**：设备名称（如「杨俊的iPhone」）
- **ProductName**：产品名（如 iPhone 17）
- **ProductVersion**：系统版本（如 26.0）
- **SerialNumber**：序列号
- **UniqueDeviceID**：UDID
- **ProductType**：内部型号（如 iPhone18,3）
- **DeviceClass**：设备类型（iPhone）
- **CarrierName**：运营商（如 CMCC CN）
- **ModelNumber**：型号（如 MG6W4）
- **DeviceCapacity** / **DeviceAvailableCapacity**：储存总容量 / 可用容量（若支持）

前端展示建议：
- **结构化展示**：用 `iosDetail` 的键值对做表格或列表（名称、型号、操作系统、序列号、UDID、运营商、储存等），与 iMazing 概览类似。
- **完整展示**：用 `iosDetailRaw` 整段原文在页面用等宽字体展示（如 `<pre>{{ iosDetailRaw }}</pre>`），这样 iOS 设备信息会完整显示、不遗漏任何一行；若 `iosDetail` 为空但设备确为 iOS，可优先展示 `iosDetailRaw`。

**androidDetail**（仅 Android/HarmonyOS 有）：分层对象，各层为键值对（部分键可能为空，以实际为准）。

| 一级键 | 说明 | 常见二级键（示例） |
|--------|------|---------------------|
| **systemInfo** | 系统与设备身份 | serialNumber, androidId, versionRelease, sdkInt, securityPatch, buildType, brand, model, manufacturer, board, hardware, deviceName, productName, bluetoothDeviceName |
| **hardwareInfo** | 屏幕与 CPU/内存 | screenSize（如 1080x2400）, screenDensity, cpuAbi, cpuCores, memTotal, memAvailable |
| **batteryInfo** | 电池 | level, status, temperature, voltage, health, charging |
| **storageInfo** | 存储 | totalBlocks, usedBlocks, availableBlocks（块数，可换算为容量） |
| **networkInfo** | 网络与连接 | wifiSsid, wifiIp, networkType（WIFI/MOBILE）, nfcEnabled, locationEnabled |
| **securityInfo** | 安全与调试 | adbEnabled, buildTags, unlockedBootloader（test-keys 为 true）, rooted |
| **sensorInfo** | 传感器 | hasAccelerometer, hasGyroscope, hasFingerprint（true/false 字符串） |

前端可根据 `platform === 'ANDROID'` 或 `'HARMONYOS'` 展示「系统基础信息」「硬件配置」「电池」「存储」「网络」「安全与权限」等区块，从 `androidDetail.systemInfo`、`androidDetail.hardwareInfo` 等逐项展示键值；电量也可直接使用顶层的 `batteryLevel`。**完整展示**：用 `androidDetailRaw` 整段原文在页面用等宽字体展示（如 `<pre>{{ androidDetailRaw }}</pre>`），即可将 Android 设备信息完整展示出来。

**响应示例（iOS）：**

**前端流程建议：**

1. 首页：`GET /devices/connected-summary` → 展示总量与设备列表。
2. 用户点击总量或某台设备 → `GET /devices/{id}/detail` → 展示详情（名称、电量、安装应用）。
   - **iOS**：除用 `iosDetail` 做结构化展示外，**务必用 `iosDetailRaw` 做「设备信息完整展示」**（整段原文，如 `<pre>`），这样设备信息会完整显示。
   - **Android/HarmonyOS**：用 `androidDetail` 各区块做结构化展示，并用 `androidDetailRaw` 做「完整原始信息」展示（整段原文）。

**设备数据获取不到时排查：**

1. **接口必须返回 200**：只要设备在列表中存在，`GET /devices/{id}/detail` 会返回 200，且至少包含 `id/name/platform` 及 `iosDetailRaw` 或 `androidDetailRaw`。若为 404，说明该 id 在库里不存在。
2. **务必展示 Raw 字段**：前端一定要渲染 `iosDetailRaw` 或 `androidDetailRaw`（例如 `<pre>{{ detail.iosDetailRaw }}</pre>`）。  
   - 有数据时：这里会是一整段设备信息原文。  
   - 无数据/失败时：这里会是后端返回的**错误说明**（如「获取失败: xxx」「ideviceinfo 未返回数据，请确认…」），便于排查。
3. **后端环境**：设备详情依赖本机命令。  
   - **iOS**：需安装 libimobiledevice（如 macOS: `brew install libimobiledevice`），设备用 USB 连接并「信任此电脑」。  
   - **Android**：需安装 adb，设备开启 USB 调试并用 USB 连接。  
   后端必须和连接设备的电脑是同一台（或能执行到该机上的 adb/ideviceinfo），否则拿不到详情。

## 一、获取设备列表（必接）

用于「设备列表」表格数据，对应截图中的：设备名称、平台、版本、状态、操作。

| 项目 | 值 |
|------|-----|
| **方法** | `GET` |
| **URL** | `{baseUrl}/devices` |
| **示例** | `http://localhost:3000/api/devices` |

**请求参数：** 无。

**响应：** `200`，JSON 数组，每项为设备对象。

**设备对象字段：**

| 字段 | 类型 | 说明 |
|------|------|------|
| **id** | string | 设备 ID（唯一，操作、下拉选择设备时使用） |
| **name** | string | 设备名称（表格「设备名称」列） |
| **platform** | string | 平台：`ANDROID` / `IOS` / `HARMONYOS`（表格「平台」列） |
| **version** | string | 系统版本（表格「版本」列） |
| **status** | string | 状态：`CONNECTED` / `DISCONNECTED`（表格「状态」列，可展示为「已连接」/「未连接」） |
| **lastSeen** | string | 最后可见时间（ISO 格式，可选展示） |
| **config** | string | 扩展配置（可选，一般前端不展示） |

**响应示例：**

```json
[
  {
    "id": "6HJDU20409003857",
    "name": "SEA_AL10",
    "platform": "ANDROID",
    "version": "10",
    "status": "CONNECTED",
    "lastSeen": "2026-02-03T18:30:00",
    "config": null
  }
]
```

**若列表为空：** 返回 `[]`。请确认设备已通过 USB 连接并开启调试，后端会定时扫描（约 3 秒一次）；也可调用下方「刷新/扫描」接口主动拉取一次。

---

## 二、刷新设备列表（可选）

手动触发一次设备扫描，再调用「获取设备列表」即可得到最新数据。对应页面「刷新」按钮。

| 项目 | 值 |
|------|-----|
| **方法** | `POST` |
| **URL** | `{baseUrl}/devices/scan` |
| **示例** | `http://localhost:3000/api/devices/scan` |

**请求体：** 无。

**响应：** `200`，响应体为字符串，如 `"设备扫描完成"`。前端可在调用后再次请求 `GET {baseUrl}/devices` 刷新列表。

---

## 三、按平台筛选设备（可选）

若前端有「按平台筛选」下拉（Android/iOS/HarmonyOS），可调用本接口直接获取该平台设备，避免前端自己过滤。

| 项目 | 值 |
|------|-----|
| **方法** | `GET` |
| **URL** | `{baseUrl}/devices/platform/{platform}` |
| **platform** | `ANDROID` / `IOS` / `HARMONYOS`（大写） |
| **示例** | `http://localhost:3000/api/devices/platform/ANDROID` |

**响应：** `200`，JSON 数组，结构与「获取设备列表」相同。

---

## 四、获取单个设备详情（可选）

用于设备详情页或操作前校验设备是否存在。

| 项目 | 值 |
|------|-----|
| **方法** | `GET` |
| **URL** | `{baseUrl}/devices/{id}` |
| **示例** | `http://localhost:3000/api/devices/6HJDU20409003857` |

**响应：** `200` 返回设备对象；`404` 设备不存在。

---

## 五、连接 / 断开设备（可选）

若前端有「连接」「断开」操作，可调用以下接口更新状态（仅更新数据库状态，不物理插拔设备）。

**连接：**

- 方法：`POST`
- URL：`{baseUrl}/devices/{id}/connect`
- 响应：`200` 返回更新后的设备对象；`404` 设备不存在。

**断开：**

- 方法：`POST`
- URL：`{baseUrl}/devices/{id}/disconnect`
- 响应：`200` 无 body；`404` 设备不存在。

---

## 六、前端对接要点（设备列表为空时排查）

1. **列表接口**：进入「设备管理」页时请求 **`GET {baseUrl}/devices`**，将返回的数组渲染到表格，列映射：`name` → 设备名称，`platform` → 平台，`version` → 版本，`status` → 状态，`id` → 用于操作列（如执行测试时传 `deviceId`）。
2. **baseUrl**：必须包含 `/api`，例如 `http://localhost:3000/api`，不能漏写。
3. **列表为空**：  
   - 先确认请求 URL 正确（含 `/api`）、无跨域或网络错误。  
   - 再确认设备已 USB 连接并开启 USB 调试（Android）或已信任电脑（iOS）。  
   - 可调用 **`POST {baseUrl}/devices/scan`** 触发扫描，再重新请求 **`GET {baseUrl}/devices`**。
4. **状态展示**：`status === 'CONNECTED'` 可展示为「已连接」，`DISCONNECTED` 展示为「未连接」。

---

## 七、curl 示例

```bash
# 获取设备列表
curl -s "http://localhost:3000/api/devices"

# 刷新/扫描设备
curl -X POST "http://localhost:3000/api/devices/scan"

# 仅获取 Android 设备
curl -s "http://localhost:3000/api/devices/platform/ANDROID"
```

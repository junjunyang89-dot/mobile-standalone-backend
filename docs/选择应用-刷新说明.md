# 选择应用（创建任务）- 刷新与无数据说明

创建任务时「选择应用」下列表来自接口 **按设备获取应用列表**。若搜不到某些包（如 `com.arca.egames.intl`），请按下面核对。

---

## 一、接口地址与参数

| 项目 | 说明 |
|------|------|
| **URL** | `GET {baseUrl}/applications/devices/{deviceId}/applications` |
| **路径参数** | `deviceId`：**必须是设备列表接口返回的 `id`**（如 `6HJDU20409003857`），不能是展示名（如 `SEA_AL10` 或 `SEA_AL10 (10)`）。 |
| **Query 参数** | **`refresh`**（可选）：`true` = 强制从设备重新扫描；不传或 `false` = 使用数据库缓存。 |

**示例：**

- 默认（用缓存）：`GET /api/applications/devices/6HJDU20409003857/applications`
- **刷新应用（必须带）**：`GET /api/applications/devices/6HJDU20409003857/applications?refresh=true`

---

## 二、为什么搜不到 com.arca.egames.intl？

1. **列表是缓存**：第一次拉取某设备应用列表时，后端会执行 `adb shell pm list packages` 并写入数据库；之后**只要不传 `refresh=true`，都只读数据库**。新安装的应用（如 `com.arca.egames.intl`）不会自动出现。
2. **前端「刷新应用」未带 refresh=true**：若点击「刷新应用」时请求的是 `.../applications` 而没有 `?refresh=true`，后端仍返回旧缓存，列表不会更新。

---

## 三、前端必须做的两件事

1. **deviceId 用对**  
   下拉选中的「测试设备」提交给接口的 `deviceId`，必须是 **`GET {baseUrl}/devices`** 返回的每项的 **`id`** 字段（设备序列号等），不能是 `name`（如 SEA_AL10）。

2. **「刷新应用」必须带 refresh=true**  
   用户点击「刷新应用」时，请求应为：
   ```text
   GET {baseUrl}/applications/devices/{当前选中的设备id}/applications?refresh=true
   ```
   用返回的列表刷新「已安装的应用」列表；之后在搜索框输入 `com.arca.egames.intl` 才能在该列表中搜到。

---

## 四、自检（仍无数据时）

1. 浏览器 Network 中确认请求 URL 是否包含 **`refresh=true`**（刷新时）。
2. 确认请求路径里的 **deviceId** 是设备 `id`（如 `6HJDU20409003857`），不是 `SEA_AL10`。
3. 直接用浏览器或 Postman 请求：  
   `GET http://localhost:3000/api/applications/devices/你的设备id/applications?refresh=true`  
   看响应里是否有 `com.arca.egames.intl`。若有，说明后端正常，问题在前端传参或未带 `refresh=true`。

按以上修改后，点击「刷新应用」再搜索即可看到包括 `com.arca.egames.intl` 在内的新安装应用。

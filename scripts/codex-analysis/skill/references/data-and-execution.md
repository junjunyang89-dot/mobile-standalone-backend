# 从待测接口到可执行用例

在用户希望准备数据、生成可执行用例、运行接口或关联平台时读取。只分析需求时不必加载本文件。

## 工作顺序

1. 读取当前需求和接口分析，确定本次要验证的业务行为及代码版本。
2. 从平台查询同项目、方法、路径的接口和已有用例，比较场景、参数、前置、断言和历史结果。接口相同不等于场景覆盖完整；复用不等于复制。
3. 读取对应测试环境配置、鉴权能力和数据库结构元数据，形成 readiness 检查。优先复用现有登录、变量和执行器，不另建一套测试库。
4. 为缺失场景形成用例修订候选和数据计划，说明为何新增/调整。只补受影响部分，保留人工维护字段、ID、旧执行记录。
5. 在授权范围内准备数据、应用已审核用例、执行测试。仅请求分析时停止在草稿；用户已经授权隔离测试环境内的常规造数和执行时，不反复请求同一项授权。
6. 从执行器收集真实响应、断言、数据库/异步证据，关联回当前报告；没有执行证据不得写“通过”。

## Readiness 是逐项事实

每个用例分别检查：
- endpoint：方法/路径、网关映射、服务版本是否对应当前代码。
- environment：选中的环境 ID、项目映射、地址和允许访问范围；只有配置存在不能标已连通。
- authentication：使用平台 credentialRef/登录依赖；Token 有效性和用户归属是否验证。存在配置不代表可鉴权。
- request：参数类型/范围/依赖组合，路径/query/body/header 变量可否解析。
- data：用户、商品、订单、券、库存等是否满足本场景状态和关联约束。
- assertions：必须有需求支持的业务断言；HTTP 状态码本身不构成成功覆盖。
- dependencies：登录、造数、异步等待和外部服务模拟是否就绪。
- authorization：用户的执行范围是否包含当前环境及这类副作用。

每项用 ready/missing/unverified/not-required，加具体原因和证据；有 missing/unverified 不自动宣称整体可执行。草稿、已准备、执行中、通过、失败、阻塞、结果不明确分别表示不同事实。

## 数据计划

先根据代码和结构确认约束，不根据表名猜外键。记录表/字段来源、枚举含义、单位、NULL/默认值、唯一键、租户与用户归属、关联表、软删除及数据生命周期。DDL 只能证明结构声明，读取测试环境元数据才能核对实际部署。

优先策略：
1. 现有合法数据：只读查询、脱敏展示，执行前重新验证状态和可占用性。
2. 业务接口创建：调用正式测试接口，保留提取变量和资源 ID；优先维护缓存、消息、库存等业务一致性。
3. 已有测试工厂/模拟渠道：核对工厂版本、状态语义和适用范围。
4. 直接写测试库：仅在已授权环境、确有必要且关联约束可说明时使用。默认不执行结构变更；不凭一条 INSERT 假装完整业务对象已建立。

每个数据计划包括 environmentId、databaseRef、策略、前置校验、参数化步骤、预期影响行数上限、runId/fixtureId、幂等策略、输出变量、业务验证、清理步骤和不可逆副作用。

并行测试使用独立数据或明确的租约。分布式流程不能靠 SQL 事务整体回滚：分别记录已提交的数据库写入、接口调用、缓存和消息操作。失败时按已完成步骤补偿；不能在请求超时后假设没有创建成功并盲目重试。

## 执行与验证

复用平台 executor、环境变量、登录缓存和前置依赖。数据库凭据、Token、服务签名密钥留在平台/凭据存储，工具只返回引用和脱敏结果；不要求把密码写进请求文件或 skill。

业务断言须可观察并对应规则：响应字段/错误码、数据库状态、库存/余额/权益数量、订单唯一性和消息处理结果。金额/比例/取整先确认规则和单位；不要把未知业务口径写成硬编码预期。

异步结果使用有时间上限的轮询，记录超时原因和观测时间窗；不是无限等待。失败分为产品缺陷、断言错误、数据不足、鉴权/环境故障、结果不明确。依赖未满足时为 blocked，不算产品失败，也不算通过。

创建/核销/发放等非幂等请求发生超时：先按业务单号或幂等键查询结果，再决定是否重试。工具层也要有 operationId，避免 Cursor 重复调用重复造数或重复执行。

一次测试可能修改数据库、缓存、消息和外部渠道。失败后的清理仍需执行；如果保留数据用于排查，记录保留原因、期限及准确资源标识。

## 清理边界

只清理本次 fixture 明确拥有的资源，用精确 ID、环境与归属谓词，并限制影响行数。不清理复用的用户数据，不使用 TRUNCATE 或宽泛按日期/名称匹配删除。先预览清理对象，超出范围就停止。

已消费卡券、已发放权益、渠道核销、通知等可能无法回滚。优先用模拟/隔离资源；不能补偿时提前明确副作用范围，并在执行后返回残留项，不能谎称“已全部清理”。

## 结果回写

保存 requirementId、analysisRevision、场景 caseId/caseRevision、平台用例 ID、接口身份、各服务 SHA、环境 ID、fixtureId、runId、断言与脱敏证据。关联同接口所有历史运行结果并不等于当前需求已测试；只引用语义及版本匹配的执行。

原分析用例是自然语言场景时，不因保存一个空请求草稿就标为已覆盖。需要具备可执行步骤与业务断言，且完成真实执行后，才更新对应执行事实。

页面只展示一份分析结果：接口下显示关联用例、具体缺项和运行结果，提供“准备测试/执行/查看结果”。内部计划、操作令牌和批次记录不要求测试逐页管理。

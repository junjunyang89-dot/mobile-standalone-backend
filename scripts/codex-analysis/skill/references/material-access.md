# 材料读取与 Figma

## 能力探测和读取顺序

1. 列出实际可用的连接器/MCP/浏览器能力。发现工具后按其说明调用，不臆造工具名和登录状态。
2. Figma 优先使用已授权的官方 MCP，读取指定 file/node 的设计上下文、结构和截图。MCP 返回的代码不是需求原文；仍需核对业务文字、状态和交互。
3. MCP 不可用而有浏览器时，打开用户指定链接，确认登录和文件权限，再定位 node。逐区读取文字、弹层、异常状态、连线与优化区；Figma 画布不一定能从 DOM 提取文字。需要视觉证据时实际查看截图，不把空 DOM 当成无需求。
4. 工具无法读取时使用用户提供的文字导出、局部高分辨率截图、PDF、Word、Excel。没有材料时继续代码侧审查，列明需求覆盖缺口；不靠图片文件名或缩略图猜需求。

每个来源保存 sourceId、URL/文件路径、node/page/sheet/区域、读取时间、可获得的版本时间、读取方式、读取成功程度、原文摘录/截图定位与未读部分。文件内容需遵守适用的引用限制。

大型设计稿先建立区域目录，然后按本需求和业务链路逐区读。记录哪些节点已看、哪些未看；不能把“主节点有截图”升级为“整份 Figma 已读完”。只读取业务相关文件，不漫游无关团队资料。

图片需核对：页面和状态名称、按钮行为、字段、错误提示、额度/期限/金额、角色差异、跳转与返回、空/加载/失败态。小字看不清则标记未辨认，不自动补全。识别出的数字、否定句和边界条件要回到图中复核。

Word 保留标题层级、表格、注释与修订口径；Excel 识别工作表、隐藏/筛选影响、单位和公式，不能只读首表。Wiki/JIRA 记录更新和评论上下文，区分讨论提议与最终确认。

若任务数据含服务端注入的 `wikiSnapshots`，优先使用其中的章节、表格、代码块、图片引用、评论和附件清单；评论标记为 comment-supplement，不得直接当成正式验收条件。折叠区 DEMO 保持未确认。接口失败时才看导出兜底。未覆盖项写在 gaps / materialGaps。

## 登录和内网边界

Cursor 官方浏览器能力不等于自动拥有用户浏览器的登录状态。账号、SSO、组织策略、网络和 Figma 权限会影响读取。登录/授权由现有安全流程处理，不绕过验证码、权限或证书告警。

本地 Agent 读取本机仓库；远程 Agent 只能读远程执行环境中的路径。云端 Agent 不能因收到 `/Users/...` 就访问用户电脑或公司内网。
